## 1. 问题与授权

当前生成工具把 2× 输入生成、W4 两档生成、完整 Preview/投影、census 与重复生成核验串在一次调用中，最后才发布 `input-summary.json`。已知错误虽有定向回归，仍缺少实际表形态的独立小样本预检，以及不受影响中间产物的显式复用。晚发现一个工具错误会使下一次调用重复此前有效计算。

Owner 在了解上述缺口后询问“能否并行完善这一部分”，授权本次工具改进。目标是提前发现工具错误、减少失败后的重复计算；不改变产品、生成数据定义、冻结测量口径或正式验收条件，不新增 S2b 开工授权。

## 3. 小样本预检

在完整生成前，扫描实际 SQL 的表结构与当前有效规则，以有界行样本运行真实生成、封包与 SQL 表物化/投影路径，覆盖 W4 10% 与 100% 两档。这是结构/规则冒烟，不另造一套声称等价于真实业务的微型数据集。

覆盖至少包括：主键与规则比较键相同/不同、复合键与可空键、无键表、空表和字符串默认值、有序位置与主键重合、特殊点保护，以及 2× 复制后规则匹配。通过明确的覆盖清单识别尚不支持的形态；不要把某一张表的回归用例泛称为全部实际表已覆盖。

实际表扫描保留 DDL、表名与规则匹配信息，按表取有界行样本；关键边界另用小型固定 fixtures 覆盖。样本须保留触发生成分支所需的行数，不能因抽样后插入配额为零而漏测插入，也不能制造与真实表无关的重复键。实际值未覆盖的边界应与固定 fixtures 的覆盖分开列示；无法正确构造某类样本时明确报告，不静默跳过并宣称通过。

有界样本可以使用 SQL-only package，但必须明确不覆盖 XML 与跨表 composite 关联完整性；不为预检新增通用依赖闭包抽样器，也不伪造关联。原完整 SourcePackage（含 XML）的 business materialization 与 canonical projection 仍属后续完整验收。SQL-only 冒烟通过不能描述为完整业务输入已验收。

预检只证明这些形态下工具流程能完成，不证明全量键唯一、全部值域、资源上限或性能。完整 Preview、投影、census 和逐表计数继续执行。记录样本规模、覆盖类别、各段耗时与工具/输入身份，日志不包含真实行内容。预检本身不应复制一遍大规模正式验收；若必要的解析成本不可避免，应单列说明。

## 4. 有界分段与复用

采用少数明确步骤和可读取的结果清单，不建设通用 workflow/recovery 状态机。具体命令参数由工具实施确定，handoff 写出新调用方式。

1. **已接受的 2× 来源。** 显式指定已接受 summary 和实际 SQL/包，核对实际字节与摘要，并核对本次 source、生成配置和规则是否适用；复制至新的输出根消费，不修改来源。历史 summary 缺少当前复用所需证明时拒绝复用，不能补造已验收事实。
2. **生成产物。** 分清 2×、W4 10%、W4 100% 的依赖及受影响范围。只完成某段不等于输入集已验收；记录该段输出摘要与生成输入身份，部分根始终不是 `INPUTS_READY`。
3. **验收。** 生成产物与校验结果分开。仅校验器修正且生成依赖未变时，可以复用字节不变的产物，重新执行受影响验收。生成逻辑或输入变化则重做相应产物及依赖它的检查。
4. **完成发布。** 全部必需检查成功后才发布最终 summary/manifest 并返回 `INPUTS_READY`；验收失败或不完整不能作为正式测量输入。

复用至少核对来源文件实际摘要/大小、相关 source package、生成参数、规则和生成实现身份；验收结果另受验收实现身份约束。普通文档提交不应使生成产物失效，也不能仅以整个 Git HEAD 相同代表输入相同。实现身份应采取保守、可审计的依赖范围，不能漏掉共享解析/规则/生成逻辑。

为支持 W4 独有修正后保留不受影响的 2× 结果，允许协调归属后把现有 W4 算法机械拆到独立模块，保持原 CLI/调用入口和输出语义。按明确物理模块计算身份，不增加动态依赖分析器或人工版本豁免；共享解析、变换 helper 或规则变化时，相关两段一起失效。

历史已接受 root 如果缺少新的分段来源记录，继续作为原测量输入使用，不自动转换为新工具的可复用分段。新工具首次生成需要建立完整分段记录，此后的同身份产物才支持分段复用。这是首次采用成本，不能宣称本次在跑的旧生成已获得断点续跑能力。

未通过最终验收的根可以作为诊断资料；仅当具体产物具备本工具明确记录并核验的分段来源与依赖时，才可复制至新根作为“待验收产物”。不因为文件存在或手填摘要就把旧失败根变成可信来源。路径、archive、symlink/root 边界按现有工具约束保持，不新增同 euid 恶意进程的防护模型。

完整 Preview/canonical projection、全部 census COMPLETE、逐表 W4 计数、已接受 2× identity、重复生成 SQL/package SHA 和 expected-input manifest 要求不取消。首次完成一组新的生成逻辑与输入时，仍做既定重复生成确定性验证；本次不把它替换为小样本测试。任何已有验证结果的复用必须能明确证明相关输入与实现未变，否则重跑。

## 5. 验证与交付

在 05 运行 focused 工具测试及五包 Ruff/mypy。测试使用有界 fixtures，覆盖真实生成路径的上述关键形态、复用命中、输入/规则/代码变化拒绝复用、文件损坏、未完成状态、仅验收修正、来源不可变和失败后不发布 READY。用必要的调用观测证明命中复用时确实没有再次执行对应昂贵生成步骤，不只比较输出文件是否存在。

不为本工具修订重跑全部产品 runner、大规模合成生成或已通过基准场景。若实现触及当前范围外的容器/产品边界，应先交设计和审核确认相应验证，而不是自行扩大任务。节点占用、LAN 源码传输、offline 环境、日志位置与起止 HEAD 等按 AGENTS 执行。

交付包含候选提交、文件清单、命令示例、分段依赖/失效规则、预检覆盖与规模、focused/静态日志和 SHA，以及尚未做真实大输入运行的限制。小样本测得的耗时不能外推为已证明节省数小时。审核后由基准实施者协调在后续实际需要生成时采用；当前生成成功则优先完成既定验收并冻结复用，不为了展示新工具另做一轮大生成。
