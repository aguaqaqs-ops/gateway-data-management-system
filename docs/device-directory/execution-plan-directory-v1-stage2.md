## 4. 运行入口与源码冻结

阶段 1 的 `directory/scripts/run-tests.sh --service/--frontend` 仍是组件入口。阶段 2 新增窄入口 `directory/scripts/run-real-journey.sh` 及目录自己的浏览器旅程配置/用例，放在 `directory/`，不改网关前端入口和配置，不复制处理组管理算法。

入口的最小接口由实施者实现为：`--head <完整 SHA> --session <唯一名> --config <私有运行配置文件> --evidence-dir <树外新目录>`；非零立即停止依赖步骤，保留真实 exit；无自动重试。它只编排既有部署/helper、目录 CLI 与真实浏览器流程，不建设通用门禁平台。配置不接受随意 shell 命令，所有进程用参数数组。

- 入口负责取得并释放节点占用；外层不再 mkdir。持有占用时不能嵌套调用另一个自行取整机锁的入口。可读 `frontend/scripts/run-real-backend-e2e.sh` 参考部署与缓存准备，但不得直接把它的预置身份 suites 当目录旅程，也不添加绕过锁的通用开关。
- 运行前核 `HEAD == --head`、clean；起止均复核。运行时不写被测树；从该 SHA archive 到树外构建区，记录 source SHA、两份 npm lock 与输出产物来源。两套前端分别离线安装和构建，不混用 lock 或依赖目录。
- 旅程入口源码本身先提交、独审，再到专用节点做必要验证；不能从未提交临时脚本执行正式证据运行。私有配置、secret、缓存、构建产物及证据都在树外。
- 若修改目录 Python/前端，补受影响组件检查；现有入口分别固定 06/07，遵循其校验而不绕过。只加真实旅程编排不强制重跑阶段 1 全部截图或后端六包。阶段末引用各组件实际运行提交，不能改写日志为 V。
- 网关镜像按既有 build-input/revision 和部署校验核身份；若现有标准要求重建，在专用节点离线构建。不能为匹配 SHA 伪造 label/retag，也不能把目录组件测试当网关容器门禁。实际网关部署检查结果与镜像来源单独记录。

**程序化优先（Owner 本轮补充）：**凡能可靠程序判定的清单、原始日志与证据检查，优先由既有门禁脚本或 CI 执行，不安排模型重复逐项手工比对。本任务先复用现有入口，缺口在目录窄旅程入口中补齐；可由 CI 调用，但不为此建设新 CI 服务，也不将测试搬到开发机/公网 runner。程序检查在指定专用节点执行，原件和派生结果分开保存。

程序至少检查：

- 必填交付项和 J0–J7 结果齐全，属于预定候选及同次正式运行；起止 HEAD、clean、原始 exit、完整结束记录符合要求，不因日志含“passed”即判通过。
- 所引用原始文件存在、SHA256 相符；副本与原件一致性可读取时实算，不能访问原件时标未知，不能仅凭副本自证来源。
- lock、缓存归档和镜像身份与固定输入相符；截图清单、数量、宽度和摘要符合声明；必要的凭据扫描仅输出安全结果。
- 将可自动断言的 scope/401、UI 状态和容器 ID/StartedAt/RestartCount 比较留在旅程测试；日志检查只核这些断言的结果和来源，不重新推断业务成功。

使用普通机器可读结果记录每项通过/失败/未知及原件定位；缺字段、文件不完整、未知或失败不得自动放行。确定性程序由实施者维护，Astra 审其错误放行风险，并在专用节点做与改动相称的验证。程序报告不覆盖原始失败，不新增通用 evidence 平台。

Astra 在只读 detached worktree 审本阶段完整差异及关键证据，不重审阶段 1 所有已关闭矩阵；新发现按 owning 边界修正。Luna 集中读取程序结果，只核程序不能可靠判定的视觉/语义、未覆盖项及报告中的异常，必要时追溯原件；不重复手工计算摘要、清点文件或抄录日志。仅接触副本时明确来源限制；业务、安全或证据矛盾交 Astra，不自行改标准。协调者分别核收程序结果、独审和适用的验收核对，不将“摘要正确”当业务通过。

完成条件：J0–J7 合格；新增阻塞 findings 关闭；三项阶段 1 未知有明确结果；来源/凭据检查合格；本人资源安全收尾；一页 `docs/device-directory/stage2-summary.md` 写行为、偏差、遗留和证据索引。未知不得写通过；新偏差若影响验收交 owner，不能套用阶段 1 例外。按已确认授权连续执行到此，不在 P1/P2/每包之间等待额外开工批准。

## 9. 停止条件与正常自主处理

真正需要 owner 决定：产品/验收范围变化、新依赖、需要改 frontend/vnext、正式来源冲突、网关实际行为与 owning 设计不符、不可逆或他人资源操作、不可替代模型不可用、无法安全收尾。报告已完成项、具体阻塞、证据和最小建议；只停止受影响部分，可继续独立文档/只读检查。

已授权可逆实现、目录自身 bug 修复、有效占用等待、命令/路径错误和获准缓存补齐，由执行者/协调者处理，按实际改动完成必要独审与验证，不逐次请示。任何失败先停止本次及依赖验收，保留原始日志；有明确修正再复跑，不无变化盲重试，不把产品失败改称环境问题。阶段 2 正式全链失败后修正并重新取完整证据，旧运行不覆盖、不拼接。
