## 副本与启动绑定

运输仅包含已绑定的 run/state/launch 元数据、三卷 checkpoint、必要输入和唯一 composite
cache entry；引用路径与原 manifest 一致。先从精确已知 metadata 得到名称、摘要和大小，
不以全卷扫描代替清单。缺失缓存、镜像或路径先补齐明确方案，不默认重新生成或构建。

05 可以从已校验 checkpoint 完整物化三个 source-name volumes，再沿原 resume 入口
克隆独立目标；拒绝已存在的同名卷，核对精确名称/labels，无关联运行容器。不得造空占位卷、
复制 CT108 失败后的 live volumes 或修改原 manifest 来绕过检查。复制保留原摘要涉及的
mtime_ns、uid、gid、mode 等属性，并按原校验核对副本。

实际解释器、干净 worktree、离线依赖、Repository Service 镜像、输入/cache、卷绑定、
新项目名及资源预算须在具体 launcher 中确定。方案审核通过不自动表示这些实施事实已核验。
当前可继续精确元数据及 05 身份/容量只读核实；实际运输和 POST 待成套启动条件审核后接续。

## 观察与停止

外置入口在 POST 前确认真实 worker 的有效 Python 3.14.6 文件/行号业务栈，只允许一次 POST。
当前 py-spy 纯 Python dump 的同镜像 canary 已通过；native unwind 不可用，不宣称具有原生栈。
离散 dump 每 15 秒一次、单次最多 1 秒，无 locals、业务行或 secret，不运行 record/top。
这是 05 诊断的限定观察例外，不改变正式基准禁止挂载采样 profiler 的口径。

独立守护从 POST 前 arm 起计最多 45 分钟；两次无效 dump 按下文“采样降级”规则处理；必要守护失效、产品失败、R5 或
原停止条件触发即收束，不自动重试。目标步骤成功或失败结束后先关闭观察器，再进入原 journey
清理，避免观察器信号打断证据保存。dump 不得阻塞独立时限。

资源边界只用于此次诊断，采用轻量读取，不建立新的产品资源机制：

- 启动前宿主 MemAvailable 至少 48 GiB；相关文件系统可用空间覆盖尚需落盘的 checkpoint
  staging、源名副本、目标卷（共 3C）、输入 I、cache R、归档临时量及 10 GiB 余量。
  已占用的材料不重复从当前 df 可用值扣减；跨文件系统分别核算。
- POST 执行期间每 5 秒读取绑定 worker 的 RSS、宿主 MemAvailable 和实际数据文件系统
  可用空间。worker RSS 达到 40 GiB、MemAvailable 低于 8 GiB、任一相关文件系统可用空间
  低于 10 GiB，或必要指标不可读时，记录原因并停止此次诊断。
- 资源监测复用同一外置守护及生命周期，不新增独立监控服务。资源/预算截断属于诊断停止，
  不据此认定产品断言失败；采样阈值也不宣称连续硬上限。

## 结果与收束

保存独立结果、原 run/state、资源与观察日志、起止身份、退出码及摘要。
成功后的 DiagnosticComplete 可能使原 journey 记为 FAILED；独立报告只能陈述单步结果，
不得称完整旅程 PASS。另核 finalization_errors、容器/network 清理与卷保留。
只清理本次项目的运行资源并释放自有占用，不使用 down -v；保留原始来源、目标卷和诊断证据。
根因与正式恢复资格仍由后续独立审核判断，不由设计会话判定实施证据。

## 2026-11-06：将可选栈采样与必要守护分开

`p6catalogsubmit20261106e` 已停止并收束，不续用其运行卷。独立审核对已有日志的核查表明：两次 py-spy 解释器发现失败触发 `two_invalid_dumps`，观察器发 SIGINT，轮询的 KeyboardInterrupt 被记录为 `step_failed`；这不能认定产品失败或原 lease 复发。此前 95 份 dump 中 89 份有效，已有日志记录 136 次成功心跳，最后一份资源检查未触阈值。最后 dump 的确切瞬间没有新的 PID 身份记录，因此不追溯认定该瞬间进程绑定仍有效，也不声称已经解释 py-spy 失效原因。

为避免可选诊断工具失效再次终止业务，下一外置 observer 候选采用以下最小变化；不改变产品、HTTP/租约/心跳或原资源预算：

- POST 前仍要求同一 worker 的有效 Python 业务栈及必要守护就绪。启动时栈不可用仍不得 POST；已有 canary 可按同镜像绑定引用，不重跑旧 canary。
- POST 后连续两次 dump 无效时，仅本次已观察到的 py-spy 解释器发现错误（exit 1、非超时、固定工具输出 `Failed to find a python interpreter in the .data section`）可以进入降级检查，两次都须属于该已知类别。其他无效栈、超时、未知错误或混合错误仍沿原两次无效即停止的规则，不通用忽略。允许检查时，必须**当场重新读取**原 worker PID/starttime、数据文件系统绑定及全部必要资源指标。身份不符、读取失败或资源越线仍停止，不能只靠早先的有效栈或上一份 5 秒资源记录继续。
- 仅在本次即时复核全部通过且既有启动栈有效时，记录 `stack_observation_degraded`、两份失败记录及本次身份/资源事实，停止后续 py-spy 采样；不再发 SIGINT。明确后续业务栈存在观测缺口，不声称全程观测。降级不可自动重新启用采样或增加额外 profiler。
- 独立 guardian 继续每 5 秒核验原进程身份和资源，原 45 分钟 POST 截止、guardian 存活检查、业务轮询失败/R5 停止与关闭顺序保持。必要守护异常仍停止；不能把 guardian 崩溃、PID 变化或指标缺失当作可选采样降级。关闭时仍回收活动 dump 和 guardian。

只修改独立外置 observer 及其固定候选摘要/说明，不修改已运行脚本和证据。用少量 05 定向工具测试证明：有效身份与资源下两次已知解释器发现失败只停采且后续资源/截止仍生效；未知/混合错误或即时身份/资源复核失败仍停止；正常关闭不再发信号。复用已有 test seam 和 fixtures，不创建新监控机制或完整产品矩阵。脚本与小测试证据交独立审核，新的单 POST 候选另行固定并取得 GO，旧 r2 GO 不复用。这不是 DC68 的产品运行前操作错误重做，旧 e 运行仍为受诊断工具中止，不能改判成功。

现有栈暴露的逐行重复类型解析/排序可以并行做只读最小方案评估，但不作为本次工具修正的前置条件，不默认加入新产品优化。再次运行的必要性在于完成被采样工具打断的业务观察，而非收集更多同类栈或追求首尝 30 秒；原 lease 根因及正式恢复资格继续保留未决状态。

## 2026-11-06：双采样超时降级与一次性预算规划

Owner 要求后续超时处理先估算或给出宽裕观察窗口，避免小幅加时后反复重跑。计算完成时间、可选采样时间和产品 lease/heartbeat 等正确性期限分别设计，不将性能目标自动当作失败门槛，也不统一放大全部 timeout。

对纯计算 probe 和外层业务观察，准备候选时先复用已有同版本、同代码路径的阶段耗时、输入规模和资源峰值，说明线性扫描、排序、重复遍历及固定开销，给预计区间及一次性裕量。跨版本优化、不同数据形状、内存压力或复杂度未经确认时，不能直接按行数比例承诺完成时间；被截断的运行只能给已完成阶段耗时或该运行总耗时下界。资料不足时明确估算未知，选择受资源守护约束、足以观察目标阶段的保守窗口，经范围审核一次固定。优先用已有材料，只有确有必要才增加短小定向校准，不为估算再跑一遍全量。软预期只提示进展；硬截止是事前约定的资源/执行预算，到达时记录预算截断，不冒充产品失败。候选执行中不临场加时；预算截断后先复核估算与接续范围，不自动重跑。

当前 g 的独立结果审核见 `281b91bb71`、有限审核报告 §55：双 py-spy timeout 后观察器主动中止，产品结果未定，旧 GO 已消耗。该结论不能靠追溯改变 timeout 改成成功。下一工具候选仅扩展已发生的可选采样失败处理：

- 保持 POST 前有效真实 worker 栈、每 15 秒一次且单次 1 秒的 dump 限制。无需为取得栈而长时间延长采样，也不把采样超时直接解释为产品卡死。
- POST 后连续两次均为明确的 dump 预算到期，且各自 sampler 子进程已确认 kill/reap，才允许进入新增 timeout 降级分支。原精确双 interpreter-discovery 分支保留；未知、混合或其他无效结果仍按原停止规则。
- 第二次回收完成后立即重读同一 worker PID/starttime、filesystem device 和原资源指标；全部合格才记录两次失败、回收事实、新鲜指标和栈观测缺口，停止本轮后续 dump，继续原业务 poll、5 秒身份/资源守护和 45 分钟绝对截止。不得重置预算、重试 dump 或追加 profiler。
- timeout 和 finally 中 sampler 的 kill/reap 统一有界，kill 后等待最多 1 秒，记录 child PID、exit、reaped 与 elapsed；未确认回收不得降级，须停止并保留残留事实。该期限用于工具退出收束，不是计算任务完成期限。关闭路径不得以另一处无界 wait 抵消此约束，未核实回收不得释放节点占用。

本次不改产品 TTL、heartbeat、stall、HTTP 预算或现有 45 分钟观察上限，不改已核产品与镜像。现有材料不足以给新产品 Submit 的可靠完成时间，不用旧失败时间或合成 probe 的截断时间拼出一个精确预测。若后续确被外层预算截断，按上述方法一次重估具体窗口，而不是逐秒、逐分钟试探。

原实施者在既有角色内准备外置工具修订；以少量 05 定向工具测试覆盖双 timeout 合格降级且守护继续、即时复核失败、未回收、未知/混合仍停止及关闭回收。复用已有 fixtures，不重建镜像、不重跑小 Compose 或全量旅程。设计范围、具体工具和最终 manifest 分别由既有审核者核对；下一次业务观察仍须新项目/key/目标副本和专属一次 GO，不续跑 g 的目标卷。本节不是运行授权，不新建会话或子 agent。
