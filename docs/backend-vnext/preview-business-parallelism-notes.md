# Preview 按业务表类型并行的优化方向

2026-11-13，Owner 讨论确认记录。用于 `gw08-dual-env` 临时测试分支的后续试验，并作为未来正式优化的设计输入。当前状态为方向记录，尚未实现或验证提速；本次记录不改变正在测量的算法、N/M 或资源配置。

## 业务条件与选择

业务大表集中在几类明确的表，字段通常不多且数量接近；不同设备命中这些类型的表数量不同，但本次处理前可以确定命中集合。采用固定业务类型、动态枚举表实例的专用处理方式，不以建设通用调度池为前置目标，也不硬编码每台设备的大表数量。

表类型及其专用处理规则需在实施前结合实际输入和 owning Contract 列明；本记录不凭名称猜测类型，也不把“字段数接近”当成行宽或耗时相同的证明。未命中专用类型的表继续使用原有正确路径。

## 最小并行策略

1. 复用现有解析结果或可信 metadata，取得本次表清单、真实行数和可用字节量。行号仅指实际处理位置或总行数，不能用最大主键、GID 或 SQL 文件行号代替。不得为估重额外完整解析一遍输入。
2. 按表类型建立简单工作量估计。首次物化以当前侧行数为起点；比较看 initial 与 modified 两侧；结果生成另考虑变化记录数。变化量若需比较后才能得到，就仅用于后续阶段估计，不为准入重复比较。
3. 在单个 operation 内设置少量、受资源限制的执行通道，按估计工作量从大到小启动；一个任务完成后补入下一张合适的表。数量动态决定待处理清单和批次数，不改变整体结构。第一版不引入跨 operation 队列、独立调度服务或持久任务状态机。
4. 只有执行通道空闲且现有内存预算足以覆盖任务预计峰值时才启动。表及执行上下文必须实际支持并发，沿用既有预算、取消、租约和失败收尾的所有权规则；不能仅凭有空闲 CPU 或物理内存放行。通道上限须受产品 N 和实际 CPU 限额约束；当前 N1 基线不因本记录自动变成多核档。
5. 在表完成或固定批次边界，根据实际耗时、已处理行数和内存修正后续分配。先采用静态估重与完成补位，只有实测收益明确才加自适应；不逐行重算策略，不频繁迁移或拆分在途任务。
6. 完成顺序不决定产品输出顺序。按 owning Contract 的规范表序、记录序和摘要规则合并；结果、digest、错误语义及发布屏障保持一致。

行数是计算量的初始估计，不是内存上限证明。变长字段、排序与索引临时空间、两侧输入以及变化记录膨胀都可能造成偏差。估计式和保守系数在代表数据上标定，不能为了增加并发降低既有资源预约或绕过硬限制。多个类型共用同一 operation 的总预算，防止各自并行及内部原生线程叠加超配。

## 热点决定优化位置

先区分同类多表与单张超大表：前者适合表间并行，后者可能需要该类型的表内分块。只有主键分组、排序、跨行规则和最终摘要允许时才分块；不直接按任意行区间切开。

普通 t4 的旧 S3 样本中，首次单份 Preview 约 56 秒，FULL 约 81 秒；比较分别约 0.10 秒、两个 pair 合计约 7.85 秒，导出、产物发布与 bundle 具有更明显的成本。FULL 样本的 baseline 为已归档 v1；本轮首次双份上传采用空 INITIAL baseline，两者不可直接比较提速。原件索引见交接区的 `gw08-preview-baseline-sol/STATUS.md`。

2×t4 的 records 构建热点不能直接替代普通 t4 的判断。优先依据当前分支测量决定并行的是解析/物化、比较、导出还是产物处理；如果主要成本来自重复导出、序列化或校验，先消除有依据的重复工作，再评估并行。不能把未覆盖的端到端残差直接归为可并行 CPU 时间。

## 本轮试验与未来正式优化

本轮先保持测量基线固定，完成普通 t4 首次单份及空 INITIAL 下 FULL 双份的测量。可从现有观测取得每类/每张表的行数、输入字节、阶段耗时、内存和变化记录数；仅在无法定位主成本时补必要计时。当前讨论不自动扩大真实数据矩阵，也不启动并行实现。

后续最小试验选择实际最慢的一类表，在同节点、同输入、相同 baseline/缓存条件与明确 N/M 下比较原路径和专用并行方案。关注端到端可见耗时、热点阶段、CPU、内存和尾部等待，不只报告内核提速；不同资源档分列。必要正确性验证覆盖结果确定性、空集合/单表、设备间数量变化、任务偏斜、预算不足和取消收尾，复用现有测试 owner，按改动面选择验证。

未来正式优化从本记录及实际测量结果继续设计：明确类型识别、数据访问并发条件、工作量估计、任务内存生命周期和确定性合并边界。临时实现如被替代应删除，不保留永久双算法或兼容开关。正式方案仍遵循 [测试约定](testing-conventions.md) 和 [比例化保障政策](refactoring/formal/policies/proportional-assurance-and-risk-based-verification-policy.md)，本记录不宣称正式性能或容量验收通过。
