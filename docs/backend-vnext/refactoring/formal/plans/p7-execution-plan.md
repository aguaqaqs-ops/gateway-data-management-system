### S1a 存储布局与资源配置

内容：定义 repository/durable/canonical/comparison/export/scratch/metadata 的逻辑位置与部署挂载；全量盘点 artifact put/locate/stream/protection/cleanup 消费者；统一 N/M/E/reserve/W/K 与 Compose 限制。先在单 worker 下完成闭环。

详细设计必须决定多 root 定位方式、同对象多用途的唯一物理归属、缺挂载行为、跨 filesystem staging/copy/publish、清理边界及修改挂载的排空操作。按需直接改 ArtifactRef/Contract，不预建兼容层；同步删除替代实现和修订触及的早期文档。

退出：同盘默认与分盘配置均能实际读写/发布/清理；跨盘复制中断不发布残缺结果；权限/缺挂载/磁盘写满有界失败；保护中的 Head、Attempt、Preview/READY 产物不被删；配置与实际容器限制一致。涉及镜像、mount/权限和部署，必须当前候选必要容器门禁。

详细执行已落成：[存储资源设计](p7-s1a-storage-resource-design.md)、[A–G 执行方案](p7-s1a-execution-plan.md)。作用域为一个 environment/group、一组一 worker；S1b 归属接点随本步提供，目录路由/多组/抽取工具留给后续。

### S1b 基础统计与只读查询

设计入口：[S1b 基础统计与只读查询详细设计](p7-s1b-statistics-and-query-design.md)，Owner 于 2026-11-11 确认简化方案。复杂度优先于测量精度，产品实施按 §1 的最新授权执行。

可编码细节见 [S1b A–F 实施计划](p7-s1b-execution-plan.md)，含实际接点、schema/索引、API/权限与有限工程初值。当前独审结论及绑定摘要见页首外部报告；[旧独立复审](p7-s1b-independent-rereview.md)和[首轮记录](p7-s1b-design-review.md)保留历史事实，不冒称核收未来修订。

内容：设备库分类占用、组级公共/未归属、写入前后观测、逐尝试资源摘要、限期曲线和只读查询/导出。设备业务库独立，Dolt 内部复用交给 Dolt；同设备同对象去重，不建跨设备分摊、通用引用图或精确物理账本。基础采集复用 metadata/标准计数器，扫描有界且允许延迟。

记录保存在独立 telemetry SQLite，业务提交不等待统计写入。运行资源初始 1 秒采样、曲线 7 天、摘要/趋势 90 天；磁盘 60 秒、设备占用 10 分钟目标轮询并合并变化通知。预算不足可丢曲线/样本，明确实际覆盖。DTO/权限/OpenAPI、物理 DDL、有限缓冲/扫描/查询参数按详细设计 §7 在实施准备时具体化；容量默认值按实际记录测算，不预填虚假容量保证。

退出：分类汇总/同对象多用途、缺失、重试、失败、计数重置和范围可正确表达；统计故障不改变业务事实；查询不能越 scope、泄漏路径、触发扫描或无限返回。单 worker 的最小已确认真实链形成可查询统计，记录采集开销；具体输入/节点按 DC33 确认。不要求逐字节核平、每次提交完整增量、多 worker 或全量性能矩阵。详细页面可独立前后端建设，不是 S1b 退出前置。

P7-D23 逐尝试摘要包含现成输入形态（表数/总行数/最大表行数/SQL 字节/变化表数和行数/有序表行数）、八阶段耗时（解析/物化/比较/风险/导出/bundle/RS 导入/finalize）、各层缓存查找/命中整数及按表有界数组（名字/比较模式/前后行数/变化行数）。沿现有阶段边界计时、cache 分支整数计数；缺失 null、失败不影响业务，不新增 profiler/性能扫描/服务，不取消已批准的有界资源和目录观测。固定载荷及预算见专项计划，替代 `s3_pair_metrics` 临时路径。

P7-D24 保留：产品 N>1 开放前完成同真实输入 N=2/N=1 端到端正式结果/digest 一致核对，最迟 S5，不以多 worker/pytest 数替代。S1b 默认 N1不开放N>1，未纳入 DC33 范围则明确移交 S2a/S5。阶段已有真实 t4 旅程保存 D23 摘要/输入/配置/结果参考，不新增性能矩阵；本阶段无有效 t4 来源则移交后续最迟 S5 闭合，不能继承 BE-b 范围或预填通过。

### S2a 组内多 worker 执行与恢复

内容：重新设计启动租约判定，原子 claim 与 K 约束、健康持有者并存、过期/崩溃接管、未知 effect 恢复、单 repository writer、RS 并发约束及 worker 观测关联。

优先每 worker 一个 executor；K 可由受控 worker 数实现，W>K 时另明确原子且可恢复的槽位方案。详细设计先修订 Operation Lifecycle owning Contract；重点独审核租约/外部 effect，不建设通用调度器或多机协议。

退出：至少两个 worker 的并发、启动、取消/排空、崩溃和租约失效场景通过；同库写入不重入，迟到结果不覆盖新 owner，未知提交先核结果；一次 worker 故障不让其他健康任务被错误接管；内存预算和容器边界实际有效。

### S2b 同机独立处理组

内容：静态设备到组目录、组内设备到 repository 单一权威、每组独立 backend/control DB/RS/roots/worker 池与资源配额；新增/更新归属有版本核对和唯一写入责任。共享目录只管归属，不存业务任务、审核、租约或 effect，不引入网络文件系统或在线自动迁移。

退出：至少两组能独立运行，错误路由/越组写入被拒绝，组内健康租约与组间故障隔离成立；统计按环境/组可区分，同盘物理容量不被重复承诺。工具接口与目录 schema 在本步实施前细化；S2a 原验收仍独立成立。

### S3 调度、准入与背压

内容：交互优先、批量保底与设备公平；上传/持久队列/executor/RS 分层准入；排队、执行和恢复期限；磁盘低水位；暂停、取消、排队原因与前端/外部 DTO。

队列与公平策略在组内执行；整机预算计所有组的 worker/backend/RS 和共享余量。静态分组允许人工调整负载，不增加跨组在线调度器。

详细设计必须给出一个简单可验证的领取策略、保底/aging 和队列容量参数，明确批量暂停的作用点；检查长队列输入保护、原绝对 deadline 和 TTL 的关系。内存或磁盘拒绝不计作成功容量样本；不靠无限线程或重试维持受理。

退出：小型混合负载证明批量非永久饥饿、交互优先生效、同设备正式历史不乱序；队满/磁盘不足/超时/取消的状态和保护释放正确；不存在运行中事务抢占；前端对接按其独立测试入口验证。

### S4a 外部映射与历史回灌接入

内容：复用映射的注册/查询/禁用/导出核对；确定输入关联及结果协议；受控回灌客户端沿现有 HTTP 业务入口自动审核归档；样本分析作为明确独立用途。外部负责文件发现、版本识别和排序，本系统不再实现这些工作。

首版输入由外部逐设备有序投递：前一版本归档或无变化后继续。版本/输入冲突、同键结果回放、清库后映射重新获取、异常停链、后续独立分析、批量暂停和中断续行都必须有明确定义。程序 actor 不接受异常、不代写人工理由、不直接修改 control DB 或 Dolt；不能因旧 Workspace 占用而绕过门禁。

退出：至少两个设备、每设备多个版本覆盖正常自动归档、无变化、重复输入、结果丢失重放、阶段中断、异常后本设备停止/其他设备继续、可分析与不可分析的后续输入、FULL/MODIFIED_ONLY 正确角色。自然数据缺少某种异常时用小型明确向量补足，不声称实样本已覆盖。外部可查询导入结果、异常和资源摘要。

### S4b 设备全状态测试抽取与加载

内容：静止捕获源组一致集合，默认导出所选设备全部现存历史/审核/终态和未完成任务及必要依赖，在独立环境加载完整 backend/RS/文件集合后正常恢复或观察故障。不要求先排空所有 pending，不提供个别历史选择器或副本回合并。另交付排空后生产换组的受控流程/必要接线；不能把测试复制当生产写入责任转交。

退出：单设备代表闭包、共享依赖、未到期租约/unknown effect/PREPARED、源副本隔离、容量与不兼容拒绝均按[分组补充 §9](p7-processing-groups-and-test-extraction-design.md#9-最低验证责任)验证；缺事实不静默重建为成功。导出表清单/工具协议在本步实施前细化，S4a 回灌验收不被替代。

### S5 默认配置与试运行准备验收

内容：绑定最终产品版本、目标单机规格和实际可用真实样本，选择保守配置；检查全部接口/操作说明，完成最终门禁、分组/回灌/测试副本组合和资源边界验证。默认值必须来自 P6 最终证据及本轮观测，不复制测试节点 worker 数。

核收 P7-D24 的 N=2/N=1 同输入正确性证据及真实 t4 的逐尝试参考摘要，交付“现象到参数”映射。性能按 P7-D22：真实操作不因执行期限/租约/内存上限失败是功能要求；默认不优化，引入新机制前给真实累计阶段占比/收益/机制，最大项已处理且下一项只惠及少数操作时停止；已有缓存按实际命中率列删除候选。P7-D21撤回旧W1–W4/H1–H3/S1–S4数值目标，不改P6历史结果。

交付：配置样例与每个参数的含义/约束/生效方式、支持硬件与输入范围、已观测局限、实际资源拒绝/异常清单、只读 OpenAPI、映射及回灌客户端说明、暂停/排空/诊断/统计导出/受控重建 runbook、逐包与容器门禁 provenance、后续校准建议。

退出：总体设计 §14 满足；长期吞吐/p95 不作为本轮待补门禁，实测不达既定功能/资源边界则不能放行。实际部署与持续历史回灌另行安排，S5 不等待数据积累到任意数量。可重建部署不要求生产级长期备份平台，但必须实际验证中断恢复与原始数据重新导入流程。

## 4. 路径预算与 Contract 责任

| 范围 | 主要改动面 |
| --- | --- |
| 存储/配置 | backend `artifacts/`、`infrastructure/artifact_store/`、cache/protection adapters、`settings.py`、`bootstrap/`、`vnext/deploy/compose.yaml`；RS settings/layout 按需 |
| 多 worker/调度 | backend `operations/`、`infrastructure/control_db/sqlite_operations.py`、worker bootstrap/lifecycle，RS 资源和 writer 边界 |
| 统计 | backend application query、infrastructure 采集/记录、HTTP schemas/routes，RS 的窄占用观测接口；不让 backend 直接挂载 RS 仓库 |
| 回灌/映射 | 现有 mapping/provisioned scope、HTTP/application 适配、批量客户端/脚本；不把 test harness 直接当产品入口 |
| Contract | Artifact/Storage、Operation Lifecycle、Business Lifecycle 的实际变更，HTTP OpenAPI；更新相关黄金/测试，不保旧别名 |
| 前端 | `frontend/` 的排队/必要统计消费，单独 FE 协作与门禁 |

详细设计必须对照当前 HEAD 复核实际文件；本表不授权顺带重构其他能力。统计和多 root 不可越过 RS owning boundary：Dolt 路径与测量由 RS/部署观测 owner 管理。

## 6. 测试节点与最终门禁

P7-D25–D27、[门禁与交接规格](p7-gate-and-stage-workflow-design.md)及 main 现行 AGENTS / [testing-conventions](../../../testing-conventions.md)为准；不照搬旧节点硬分工，不以当前较早 FE 工作区覆盖 main。

### 工作包验证与阶段集中验收

| 时点 | 必要验证 |
| --- | --- |
| 阶段内各包 | 受影响静态/类型、focused/unit/Contract，必要真实filesystem/Dolt与最小数据链；不因每包/角色更换跑完整构建、runner或真实旅程 |
| 容器接线点 | 仅只能在容器证明且影响后续接线的mount/权限/entrypoint/cgroup/signal，在相关实现收敛后做最小验证，可合并关联包 |

完整容器项延期记 `deferred` 和明确执行点，不阻塞无依赖后续工作；已发现正确性问题仍须修复。同次runner已通过的Compose不重复另跑。依赖基础镜像仅当锁/工具链等定义输入变化时重建/传输；产品源码变更复用合法dependency-base和缓存。一次集中验收是正常通过目标，修复后按实际影响重建复验，不把未知写成通过。

确认的非程序逻辑构建/命令/环境故障按现行[快速修复规则](../../../testing-conventions.md#构建故障快速修复owner-2026-11-10)定位、修正、重跑失败步骤，不按固定次数机械停止、不盲重试。命令/获准环境由执行者直接修复；仓库构建源码修订由实施者修复、原审针对增量复核。一个故障条目追加原始exit/日志/SHA与修正结果，不反复新建报告。产品逻辑、编译/类型、部署语义或测试预期改变回正常实施/独审。构建成功不代表产品测试通过，真正阻塞等待明确答复。

### 节点、自动门禁与证据

- focused、真实旅程、编译及lint按main DC91/DC97现行专用节点池选合格空闲节点，先BatchMode SSH核连接/现场服务/端口/有效占用，再原子取得本节点标志；初始pytest/Cargo jobs=4。所有测试/编译/lint均遵守占用规则；stage-gate由脚本取标志，外层不重复取得。暂停按§1可保留本人仍需资源，尊重其他人的有效标志。
- 自动阶段门禁固定04及同一detached worktree `/home/dev/gdds-stage-gate`，04忙则等待后重新触发，不迁移carried来源。协调者调用 `scripts/run-stage-gate.py <完整SHA> --packages <实际受影响包> --purpose stage`；准确参数/节点配置见main `scripts/README.md`。包闭包命中/不命中及容器等价由脚本判定，不人工抄摘要冒充通过。
- clean已提交源码，linked worktree准备legacy符号链接，运行期间不写被测树。日志在worktree外，记hostname、起止HEAD/UTC、runner自身exit及SHA256；prepared manifest不能替代实际runner manifest，跨节点复制记录不能取得carried资格。
- UV_OFFLINE=1、CARGO_NET_OFFLINE=true，缓存/依赖镜像通过获准LAN预填充，无公网或转发代理取证。缺缓存停止受影响执行，补齐后按规则新运行，不改在开发主机测试。Rust改动后backend focused重装扩展并核build input。
- 镜像/部署/runtime边界变化按现行触发规则在当前候选本机离线构建与验证，跨节点身份比config digest和全部RootFS DiffID。记录HEAD、触发/延期理由、最后image revision/source-tree及来源。

runner非零停止该次及依赖验收，不录入部分包通过、不继续carried；保留原始失败再按分类修复。阶段门禁可同来源节点/同固定worktree查表，最后仅文档H也由脚本重判；S5、发布、production强制fresh六包并在最终HEAD重建完整门禁。前端如有变更独立执行FE权威入口及适用截图，不由后端包结果代替。

每阶段真实范围在准备时按实际改动列清并由Owner依DC33一次确认；范围不因完整实施授权或缓存命中自动扩大。S5至少验证有依据的正常/无变化/异常样本及两个设备的有序回灌，核D24移交；功能覆盖不冒充大规模压力或性能通过。目标机器不足某档位不超配，明确支持范围。
