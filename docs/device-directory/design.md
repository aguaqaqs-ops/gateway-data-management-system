# 设备目录系统设计（试运行版）

状态：原业务设计及 Q1–Q5 已由 owner 于 2026-11-11 确认。2026-11-12 针对 `main@eb6530b36e` 的处理组接入修订为**待 owner 确认的草案**（见 §12）；尚未据此恢复产品实现或完成验收。接口细节见 [interfaces.md](interfaces.md)，草图见 [sketches/](sketches/)。

## 1. 目标与范围

设备目录是独立于网关机数据管理系统（下称“网关系统”）的一套小系统，作为试运行阶段进入网关系统的入口：

- 按 地区一 → 地区二 → 项目 三层浏览，或按项目名、站号、拼音首字母搜索；
- 选中项目后跳转到网关系统中该设备的数据提交树，之后的上传、Preview、提交、审核、历史比较都在网关系统内完成；
- 目录名单由外部程序导入，目录系统为每个项目生成设备唯一键。

**不做：**权限系统；一个项目多台设备；在目录中显示提交、审核等状态；正式 SSO；规模评估。这些放到正式运行阶段再决定（§10）。

**与现有网关系统原则的关系：**网关系统中“一个会话对应一个网关设备与业务项目、切换设备即切换会话”（前端 kickoff §4.3，FD2）不变。目录系统负责为每个设备签发会话，“切换设备”就是回到目录、换一个设备重新进入。

## 2. 已确认的业务约束（owner，2026-11-11）

| # | 约束 |
| --- | --- |

| B2 | 不设计权限，所有人都能看到全部项目。以后的权限系统也独立于网关系统，网关系统自身不做身份认证 |
| B3 | 主要使用者是审核人，但试运行要能走通上传、浏览、审核的完整流程 |

| B5 | 地区和项目名单由外部程序导入，目录系统只约定导入规则 |

## 3. 总体结构

```
 外部导入程序 ──CSV──▶ ┌────────────────────────────┐
                        │ 目录命令行（运维）           │
                        │  import    导入目录名单     │
                        │  provision 开通设备         │──┐ 调用现有宿主管理工具 add-device
                        └────────────┬───────────────┘  │ 预留 → 登记建仓 → 会话 → 路由发布/探针
                                     │ 读写               │ renew-sessions：按现有锁替换会话
                              directory.sqlite3           │ 处理组与公共入口由运维预先部署
                                     │ 只读               ▼
 浏览器 ──▶ 目录服务（HTTP，单进程）                网关系统（公共入口 + 一个固定处理组）
           ├─ 目录前端（静态文件）                         ▲
           ├─ GET  /api/catalog                            │ Bearer token
           └─ POST /api/handoffs ──▶ 跳转地址 ──▶ 网关前端（片段携带会话）──┘
```

- **目录服务**只读自己的 SQLite，运行时不写网关系统的任何文件，也不调用网关接口。
- **目录命令行**是唯一会碰网关系统的部分。新增设备复用 `vnext/scripts/manage-processing-groups.py add-device`，由网关拥有预留、建仓、scope/INITIAL 登记及路由发布。目录只在续期时按现有宿主锁协议原子替换自己管理的会话，不直接写 seed 映射、处理组清单或路由目录，不自行重载入口。
- **试运行部署**固定使用一个由运维预先部署的处理组及公共入口；组清单提供环境、端点、会话目录和凭据文件路径。目录不创建组、不自动分组、不迁移设备。业务目录 SQLite 与网关 `device-directory.json`（设备到处理组的预留表）是两个不同对象。
- **网关前端**需要补一个小入口：从跳转地址中读出会话（§7.3）。这是网关系统唯一的代码改动，位于 `frontend/`，不涉及 `vnext/`。

**代码位置：**仓库根目录新建 `directory/`（服务、命令行、前端都在其中）。不放进 `vnext/`，避免改变后端测试闭包与镜像身份；也不放进 `frontend/`，保持与网关前端相互独立。

## 4. 数据模型

目录 SQLite 中三类数据：

| 实体 | 字段 | 说明 |
| --- | --- | --- |
| 地区 | 地区一名称、地区二名称 | 以名称路径为标识；改名视为新地区（试运行可接受） |
| 项目 | 站号（主键）、项目名、地区一、地区二、拼音首字母（可多个）、全拼（可选，可多个）、设备键、项目号、是否已移除 | 站号决定设备键；项目改名、换地区时设备键不变 |
| 开通记录 | 设备键、环境/组、当前会话及到期时间、待生效会话及到期时间、仓库 ID、初始提交号、初始基线节点 ID、开通时间 | 先保存待生效会话供中断重跑；网关登记结果只作回执，成功确认后才可跳转 |

另记一条目录元数据：目录版本、导入时间、导入文件 SHA256。导入或 `provisioned` 的可见值变化时更新目录版本，保证 I3 的 ETag 与实际响应一致；开通不改变导入时间和导入文件 SHA256。

**唯一键（B4）：**由规范化后的站号确定性生成，同一站号在任何时候、任何机器上生成的键都相同。规则见 [interfaces.md I2](interfaces.md#i2-唯一键规则)。键不含名称和地区，所以改名、换地区不影响已开通的设备。正式运行时键改由其他系统导入；按项目前提，届时直接改为新规则并重建试运行数据，不做兼容。

## 5. 导入（B5）

- 格式为 UTF-8 CSV，字段与校验见 [interfaces.md I1](interfaces.md#i1-目录导入文件)。
- **整份替换：**每次导入都是完整名单。校验全部通过才生效，任一行出错整份拒绝，并逐行报告错误。
- 站号重复、必填字段为空、拼音格式不合法、生成的设备键冲突，都会拒绝。
- 名单中消失的项目标记为“已移除”：目录中不再显示，开通记录与网关系统中的数据都保留；以后重新出现时恢复。
- 导入结束输出摘要：新增、更新、移除、恢复、不变各多少条。
- 支持 `--dry-run`，只校验并输出摘要。

导入只改目录自己的数据，不触碰网关系统，不需要重启任何服务。

## 6. 开通（provision）

“导入目录名单”与“网关开通设备”仍是两步。运维先按网关现有流程部署处理组与公共入口，核对镜像、预算、父目录挂载及管理工具的检查结果；目录不承担首次基础设施部署。

### 6.1 新增设备

1. 选择站号列表或 `--all`（包括未完成开通的项目），全部校验站号、固定目标组、现有预留冲突及容量。任何预检失败都不开始新增。
2. 对每个设备，先在目录 SQLite 保存目标环境/组和随机待生效会话，写出仅含该设备会话的私有临时文件。中断重跑使用同一会话；待生效会话已过期时停止并报告，不自动换 token 绕过恢复。
3. 通过可替换的宿主适配器调用现有 `manage-processing-groups.py add-device`。由该工具执行：预留 false → 组内幂等登记/建仓 → 追加会话 → 本组 scope 探针 → 预留 true → 入口校验/发布 → 实际加载与公共 scope 探针。目录不在外层重复持有该工具自行获取的宿主锁。
4. 工具 exit 0 后，查询内部 registration 取得并核对环境、组、设备、项目、仓库与固定 INITIAL 回执；通过公共 `/v1/device-context` 用本次 token 核对相同 scope。目录保存回执、将会话转为当前会话并记开通时间，此后 `provisioned=true`。

**成功边界：**只建成仓库、登记成功、目录文件 enabled=true 或 HUP 成功，均不表示开通完成。管理工具 busy/未完成时，报告当前设备与已完成列表，不自动重试写操作；下次明确运行以相同设备/项目/环境/组恢复。不得改组、换设备键或扫描 Dolt 推断结果。已完成项保留，未完成项不签发跳转。

**归属与标识：**目录继续按站号生成设备键和项目号；建仓幂等键与初始基线节点 ID 由网关生成，目录只保存登记接口返回值。当前 Head 不作为 INITIAL 回执。

### 6.2 会话续期

`provision --renew-sessions` 为所有曾开通设备（含当前已移除项目）更换 token 并延长有效期；不建仓、不改路由、不重启 backend/worker。它不能通过再次调用只追加授权的 `add-device` 实现旧 token 撤销。

1. 串行化本系统的管理命令；按网关现有顺序获取全局 publication lock，再获取目标 group management lock，锁冲突返回 busy。锁内重读清单和 session 文件。
2. 依据 SQLite 中保存的会话完整内容识别本系统条目；不向网关 JSON 加 `issuer`。旧条目缺失或被外部改动时报告冲突，不按 actor_id 或 token 前缀猜测归属。其他合法会话保持原内容和顺序。
3. 先在 SQLite 持久保存本轮待生效会话，再按组构造完整候选文件，按现有宿主管理工具的严格 session schema、跨组 token 唯一性和大小上限校验；同目录临时文件、保留权限/属主、文件 fsync、replace、父目录 fsync 后发布。
4. 核对新 token 的公共 scope 探针及旧 token 后续新请求返回 401，再把待生效会话转为当前会话。已受理请求不在撤销范围内。只在全部目标确认后报告续期成功。

SQLite 与 session 文件不组成分布式事务。中断后保留待生效会话，重跑若发现文件已是该候选则只确认并收尾，仍是原文件则继续发布；未知内容报冲突，不回滚已生效会话或重建业务数据。续期未收尾的设备暂停签发 handoff，返回 `SESSION_UPDATING`。不增加注册任务表或第二套网关恢复流程。

**已知限制：**每个开通设备对应一个 Dolt 仓库。网关现有硬上限为路由目录最多 10000 设备/8 MiB、每组 session 文件 1 MiB，续期也要遵守；导入名单可以更大，但不代表可全部开通。按实际需要分批开通，预检报告容量不足，不放宽上限；完整规模评估仍不在本轮范围。

## 7. 会话与跳转

### 7.1 会话

- 身份 `actor_id = "test1"`（B9），授予网关系统全部 7 项权限（[I4](interfaces.md#i4-会话文件与续期)），一个身份就能走通上传、Preview、提交、审核、撤回、历史比较和归档。代码中未发现“不能审核本人提交”的限制。
- 每个已开通设备一条会话，token 为随机值，开通时签发。
- 有效期默认 180 天，可配置；到期前用 `--renew-sessions` 续期。
- 网关系统中的工作区按 `actor_id` 划分，所有人以 `test1` 进入同一设备时共用同一个工作区。试运行只有一个身份，这一点可以接受；多人同时操作同一设备时，需要先线下约定。

### 7.2 跳转

1. 用户在目录中点击“进入提交树”。
2. 目录前端调用 `POST /api/handoffs`，取得跳转地址。
3. 浏览器在当前标签页打开网关前端，地址片段（`#` 之后，不发送给服务器）携带 token、设备键、项目号、显示用的地区路径与项目名，以及返回目录的地址。

### 7.3 网关前端需要补的入口（`frontend/`）

- 启动时若地址片段中有 `gdds-handoff`，解析后设置 `window.__gatewaySession`，随即用 `history.replaceState` 清掉片段。
- 把会话保存在 `sessionStorage`（只在当前标签页内有效，关闭标签页即失效），这样刷新页面后仍在原设备内。这是对现有 `authenticated-fetch` “不在浏览器存储中持久化凭据”约定的试运行例外（Q1，owner 已确认），正式运行接入 SSO 时重新决定。
- 标题栏显示“地区一 / 地区二 / 项目名（站号）”和“返回目录”链接。
- 没有会话时显示“未选择设备，请从设备目录进入”。
- 设备尚无数据（只有初始基线）时，提交树显示“尚无数据”，上传入口照常可用（B7）。网关后端支持在空的初始基线上完成第一次提交，Compose 门禁旅程就是这样走的；工作台在只有初始节点时的显示要在 07 节点上实测，再决定提示放在哪里。

不同标签页可以分别进入不同设备，互不影响。

## 8. 目录前端

布局按草图：左侧两层地区树（带项目数），右侧项目表，顶部是全局搜索与最近访问。

- **数据加载：**一次取回完整目录（[I3](interfaces.md#i3-目录服务-http-接口)），带 ETag。约 1.8 万条、压缩后约 0.5–1 MB；地区树、筛选、搜索都在浏览器内完成。
- **地址状态：**`?r1=&r2=&q=&scope=&page=`，从网关系统返回后恢复原位置，链接也可以转发。
- **搜索：**不区分大小写，匹配项目名子串、站号前缀、拼音首字母前缀与子串、全拼子串（导入方提供全拼时）。范围可选“全部地区”或“仅当前地区”。搜索时，左侧数字变为各地区的匹配数。
- **排序（B8）：**按全拼排序，导入方未提供全拼时按项目名的字符编码排序；名称相同的再按站号排序。
- **同名标记：**全目录中名称相同的项目都带“同名”标记，悬停时显示同名数量；靠站号区分。
- **未开通：**“进入”位置显示“未开通”，悬停说明“该设备尚未在网关系统开通”。
- **最近访问：**保存在 `localStorage`，最多 10 条，只存设备键；目录中已不存在的条目自动丢弃。
- **分页：**每页 50 条；↑↓ 选择，Enter 进入，`/` 聚焦搜索，Esc 清除搜索。
- 视觉沿用网关前端的配色与字号，复制所需 token，不依赖 `frontend/` 的代码。

## 9. 部署与测试（试运行）

**部署（B10，同机）：**

- 目录服务单进程，默认端口 8100，配置项见 [I7](interfaces.md#i7-配置)。
- 网关前端以 `vite preview`（或同类静态服务）运行，通过已有 `GATEWAY_FRONTEND_ENTRY_ORIGIN` 把 `/v1` 代理到网关公共入口。单组也沿用公共入口，内部管理请求只走清单派生的本机组端点。
- 目录命令行具有运行既有宿主管理工具所需的清单、session、管理凭据文件及 Docker 权限；secret 不放 argv、不写日志。目录服务只读自己的 SQLite，不获得这些网关权限。
- 会话实际宿主路径为目标组 `session_directory/session.json`，Compose 只读挂载其父目录，原子替换无需重启；不再以容器内 `GATEWAY_BACKEND_SESSION_FILE` 充当宿主路径配置。

**测试：**

- 目录：导入校验、唯一键生成、搜索与排序、跳转接口的单元测试，在 06（后端）和 07（前端）节点运行。
- 网关前端入口：单元测试和 mock e2e，在 07 节点运行。
- 端到端：在 05 节点上导入样例名单 → 开通 2 个设备 → 从目录进入 → 上传 → Preview → 提交 → 审核 → 返回目录切换设备。
- 试运行阶段，目录不并入两个权威测试入口（Q2，owner 已确认）。

## 10. 正式运行前再决定

- 设备唯一键改由其他系统导入（B4），目录不再生成。
- 权限与身份：接入独立的权限系统或 SSO，按人签发会话，替换 `test1`。
- 在目录中显示提交、审核状态：需要网关系统提供按设备批量汇总的只读接口。
- 一个项目多台设备：项目表中的行改为可展开的设备子行，跳转仍以设备为单位。
- 规模评估：仓库数量、会话文件大小、开通耗时。
