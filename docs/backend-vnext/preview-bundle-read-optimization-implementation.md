## 2. 角色和并行安排

| 角色 | 模型/思考等级 | 职责 |
| --- | --- | --- |
| 持续协调者 | 建议 Terra xhigh | 范围、风险、工作区/节点资源、合入、运行预算、阶段日志、长测等待监控、收尾与核收 |
| 实施者 | `gpt-6.1-terra` / `xhigh` | 分包实现、必要工具/测试、本人 focused、修复及证据交接 |
| 独审者 | `gpt-6.2-sol` / `xhigh` | 新上下文只读固定 diff，核 Contract、正确性、安全与工具放行风险及必要证据；原 finding 复审 |

所有子任务 `fork_turns=none`，明确传入本设计/计划、Owner 专项模型授权、固定 SHA/范围、工作区、输出路径和权限。审核者不用实施者上下文、不得修改产品或验收标准、不得私自重跑。协调者可分多组，如产品+审核、旅程工具+审核、按故障临时排查+原审复核；不要求每组常驻，也不为凑并行拆极小 helper。

最多按工具真实可用槽启动；当前参考为含协调者共 4 槽，即最多 3 个活动子 agent。通常先并行 P1/P2，释放槽后审核。禁止多个 agent 写同一文件或测试树；短期工作区按文件归属隔离，合入由协调者串行执行。默认只由协调者派直接子 agent，不自动递归扩队。

并行代码分析不等于并行使用同节点。正式计时期间同节点整机单飞，其他 agent 可在开发侧读代码/写未被测的隔离工作区；不得影响该组镜像、输入或存储。按实际物理宿主干扰协调，不假设不同 SSH 名即硬件隔离。

## 4. 输入准备与运行脚本

优先阅读 `vnext/backend/benchmarks/real_dump_journey.py` 的上传、Preview、submit、approve、archive、同 operation 结果可读与计时辅助代码，以及现有 test support；其完整默认旅程可能包含额外 Preview，**不能直接运行默认全旅程来代替 12 次限定计划**。参数、scope、输入打包方式由 P2 从当前源码确认，不在设计中编造已存在的 CLI 开关。

P2 输出一套具体可运行命令及预期行为到 RUN-PLAN：源码/工具 SHA、镜像身份、输入路径及摘要核对、离线缓存、端口/卷/workspace 归属、MO 的 Submit→Review APPROVE→Archive 顺序及业务 baseline 核对、F 插入点、轮询/有限超时、断言、下载和证据路径、异常清理及接续边界。必要的窄 harness 可实现，但不得绕过真实 API、直接写 DB 建业务状态或改产品输出。

冻结 `k` 后两版一致；F 在对应 Mk 前执行，使用同仓库当时已归档业务 baseline；优先另一 workspace（先核 actor/workspace 唯一性），或同 workspace 经版本核对后重新上传 MO，F 不提交，避免修改 MO 主链。必须先从源码验证 workspace baseline 规则支持该安排。若不支持，最小重编排需保持总预算和同逻辑状态；不得把新真实 Preview 当“准备”而漏计。

若另一 actor 执行 F，必须用该 actor 身份一致的独立 HTTP client，或经审核的窄适配；旧 `_preview(token=...)` 只覆盖 POST token，后续 workspace/结果 GET 仍用 client 默认身份，仅换 token 不够。

旧 `_assert_preview_summaries` 含冻结数据假设，不能原样套五份新输入；当前受理到可读计时使用 2 秒轮询时，必须记录该分辨率，bundle 下载位于该计时之后则另记。旧 Preview-only 脚本不支持提交链，不能只改路径就算完成。

预检查输入与 packaging 不调用真实 Preview。在专用节点占用内核输入格式、差异和身份，记录哪些业务预期独立成立。真实原件不改写，输入打包副产物放本次运行目录。准备过程不能隐式跑全量 census、全量产品旅程或预热矩阵；仅作当前接口所需最小准备。

## 5. 验证顺序与门禁

1. **源码/文档核对**：P1 责任表及 P2 调用预算/状态构造，先消除 Contract 与工具语义冲突。
2. **focused**：固定已提交测试树在合格节点运行；优先现有 bundle 测试与实际受影响消费者，工具改动用小向量检查受理计数、失败停止、结果等待及恢复，不为工具自测消费五份真实 Preview。serial 组 `-n 0`，不盲目 xdist。
3. **静态**：五 Python 包全部 ruff/mypy，使用 `uv-consume.sh`；包名与命令由现行 runner/项目配置确认。不在开发机 lint/编译。Rust 无改动不额外编译检查。
4. **独审收敛**：Sol 核完整 diff、focused 与工具结果，产品错误不能归作环境故障；修复由 Terra 做、同 finding 原 Sol 复审。
5. **集中权威门禁**：在开发节点调用 `scripts/run-stage-gate.py <完整候选SHA> --packages <实际闭包包列表> --purpose stage --session <本阶段会话名>`。占位值必须替换为已核值，包列表不机械只写 backend，也不默认六包 fresh。04 固定树/占用/查表/容器由入口管理，不外层重复拿标记。
6. **真实对照**：双方工具等价且已有检查通过，协调者启动限定计划。源码/镜像/输入冻结，记录计时组和实际 SHA；不在运行中修源码或重建镜像。门禁失败停止依赖验收，不能照跑并冒称合格。
7. **最终候选核收**：阶段末独审覆盖所有最终差异；若去观测补丁或摘要文档导致 HEAD 变化，必要门禁按脚本重跑/沿用并绑定最终 HEAD。旧镜像证据不能直接称当前 HEAD 已验证。

五包静态是代码提交要求，不能由“只改一个 helper”豁免。阶段实现按现行提交与检查规则推进；测试/审核快照如需先提交固定候选，标明待验证，不当成已验收交付。新增/改动测试遵守 artifact ID builder、真实 Dolt integration、时间敏感 serial 和避免纯校验依赖真实仓库的规则。

focused/静态和阶段门禁不消耗 12 次真实 Preview；任何入口如果内部使用本轮真实五份数据触发 Preview，必须纳入台账，不能以入口名规避额度。项目 S5/发布/production 的六包 fresh 另有强制规则，本任务不代替它们。

## 6. 节点、监控和故障修复

实际执行前读最新测试规范的执行入口、长时间执行、网络缓存、触发式重建和问题影响评估与接续段。自动门禁固定 04，其余从五节点池选择空闲、工具/缓存/输入合格节点；不默认在 gw08 联调环境做正式性能对照。所有测试、编译、lint、构建、输入/产物取证均在专用节点取得原子占用；纯现场只读检查例外不扩大到业务原件读取。入口自己管理标记时不重复取得。离线缓存不齐先修条件，不经转发代理运行证据。

手工运行满足 legacy 链接、磁盘 TMPDIR、源/工具/镜像身份和原始退出码记录；真实持久状态不用 tmpfs。脚本 runner 的失败保留，修复后新运行，不拼成功日志。镜像不得以 inspect ID 跨节点判断等价，使用 config digest 与全部 RootFS DiffID。

阶段门禁、集中真实旅程和测试日志的持续监控由**协调者**负责。优先退出/异常通知，必要时低频只读核进度；无需实施者或审核者常驻轮询，不创建专职监视 agent。实施者本人短 focused 仍自行执行和收尾。若实施者启动长进程，交清节点、PID/会话、SHA、日志、占用/服务/卷及收尾责任，协调者明确接手后保持唯一执行 owner。

发现问题直接派 Terra xhigh 排查/修复，必要时按互不重叠范围并行分组，无需逐次请 Owner 同意。派单包含最小复现/日志、失败运行、受影响范围、允许写的工作区；远端取证仍由占用 owner 组织，不许排查 agent 绕过标记读归档。需要代码复审回原 Sol；新风险或另一包可新建独立 Sol 上下文，但不冒名为原审。

修复前后由协调者记录影响：哪些结果有效/失效、最小 focused、最早受影响步骤、checkpoint/输入/源码适用性及剩余额度。先 focused，再从有效状态接续；性能对照不得把不同产品版本的片段拼成同条件完整样本。超 12 次、产品/验收范围变化、来源冲突、不可逆操作或他人资源才交 Owner 决策。

已确认命令/路径、获准缓存或安全临时空间错误按快速修复规则直接处理并重做失败步骤；每次有具体修正，不设机械次数上限、不盲重试。源码编译/类型/运行时错误按产品 finding。失败现场和原件保留；收尾只释放本人标记，不删他人资源、不全局 prune、不批量清历史 worktree。
