## 3. 小样本预检

在完整生成前，扫描实际 SQL 的表结构与当前有效规则，以有界行样本运行真实 SQL 生成与 SQL 表物化/投影路径，覆盖 W4 10% 与 100% 两档。这是结构/规则冒烟，不另造一套声称等价于真实业务的微型数据集。预检直接消费 SQL bytes，不宣称覆盖封包/staging；封包由已有独立回归及完整生成验收覆盖，不重复建立同一不变量的测试。

覆盖至少包括：主键与规则比较键相同/不同、复合键与可空键、无键表、空表和字符串默认值、有序位置与主键重合、特殊点保护，以及 2× 复制后规则匹配。显式区分 SQL NULL 与空字符串键，已发生 KEY_EMPTY 的键默认值路径须对应到实际表形态及非零插入配额；已有回归承担该不变量时不重复建测试。通过明确的覆盖清单识别尚不支持的形态；不要把某一张表的回归用例泛称为全部实际表已覆盖。

实际表扫描保留 DDL、表名与规则匹配信息，按表取有界行样本；关键边界另用小型固定 fixtures 覆盖。样本须保留触发生成分支所需的行数，不能因抽样后插入配额为零而漏测插入，也不能制造与真实表无关的重复键。实际值未覆盖的边界应与固定 fixtures 的覆盖分开列示；无法正确构造某类样本时明确报告，不静默跳过并宣称通过。

SQL-only 样本必须明确不覆盖 XML 与跨表 composite 关联完整性；不为预检新增通用依赖闭包抽样器，也不伪造关联。原完整 SourcePackage（含 XML）的 business materialization 与 canonical projection 仍属后续完整验收。SQL-only 冒烟通过不能描述为完整业务输入已验收。

预检只证明这些形态下工具流程能完成，不证明全量键唯一、全部值域、资源上限或性能。完整 Preview、投影、census 和逐表计数继续执行。记录样本规模、覆盖类别、各段耗时与工具/输入身份，日志不包含真实行内容。预检本身不应复制一遍大规模正式验收；若必要的解析成本不可避免，应单列说明。

## 4. 有界分段与复用

采用少数明确步骤和可读取的结果清单，不建设通用 workflow/recovery 状态机。具体命令参数由工具实施确定，handoff 写出新调用方式。

1. **已接受的 2× 来源。** 显式指定已接受 summary 和实际 SQL/包，核对实际字节与摘要，并核对本次 source、生成配置和规则是否适用；复制至新的输出根消费，不修改来源。历史 summary 缺少当前复用所需证明时拒绝复用，不能补造已验收事实。
2. **生成产物。** 分清 2×、W4 10%、W4 100% 的依赖及受影响范围。只完成某段不等于输入集已验收；记录该段输出摘要与生成输入身份，部分根始终不是 `INPUTS_READY`。
3. **验收。** 生成产物与校验结果分开。仅校验器修正且生成依赖未变时，可以复用字节不变的产物，重新执行受影响验收。生成逻辑或输入变化则重做相应产物及依赖它的检查。
4. **完成发布。** 全部必需检查成功后才发布最终 summary/manifest 并返回 `INPUTS_READY`；验收失败或不完整不能作为正式测量输入。

复用至少核对来源文件实际摘要/大小、相关 source package、生成参数、规则和生成实现身份；验收结果另受验收实现身份约束。普通文档提交不应使生成产物失效，也不能仅以整个 Git HEAD 相同代表输入相同。实现身份应采取保守、可审计的依赖范围，不能漏掉共享解析/规则/生成逻辑。

依赖/失效表显式包含 `datasets.json` 和继承的 `baseline_census` 来源身份；两者变化时重算受影响清单、census 与验收，不必无条件重生成 SQL。保留原有 v1/v2 未变化副本检查、manifest/census dataset 集合一致及 ordered census 完整性，不能以文件摘要相同替代这些检查。

为支持 W4 独有修正后保留不受影响的 2× 结果，允许协调归属后把现有 W4 算法机械拆到独立模块，保持原 CLI/调用入口和输出语义。按明确物理模块计算身份，不增加动态依赖分析器或人工版本豁免；共享解析、变换 helper 或规则变化时，相关两段一起失效。

历史已接受 root 如果缺少新的分段来源记录，继续作为原测量输入使用，不自动转换为新工具的可复用分段。新工具首次生成需要建立完整分段记录，此后的同身份产物才支持分段复用。这是首次采用成本，不能宣称本次在跑的旧生成已获得断点续跑能力。

未通过最终验收的根可以作为诊断资料；仅当具体产物具备本工具明确记录并核验的分段来源与依赖时，才可复制至新根作为“待验收产物”。不因为文件存在或手填摘要就把旧失败根变成可信来源。路径、archive、symlink/root 边界按现有工具约束保持，不新增同 euid 恶意进程的防护模型。

完整 Preview/canonical projection、全部 census COMPLETE、逐表 W4 计数、已接受 2× identity、重复生成 SQL/package SHA 和 expected-input manifest 要求不取消。首次完成一组新的生成逻辑与输入时，仍做既定重复生成确定性验证；本次不把它替换为小样本测试。任何已有验证结果的复用必须能明确证明相关输入与实现未变，否则重跑。

父进程汇合后核对各档首次/重复 SQL 与包摘要，保留原完整逐表 inserted/deleted/updated、ordered 位移及 unavailable 信息，才可发布对应阶段 receipt。失败、硬退出或取消时回收本次全部子进程；已完整核验的独立分段可保留，未完成阶段不发布成功记录或 READY。沿用明确的物理依赖身份规则，不为调度修订手工豁免旧记录；身份变化的保守失效可接受，不能追写历史生成事实。历史 full4 诊断产物显式导入仍是[单独评估](p6-w4-full-input-import-assessment.md)，不并入本轮接线。

预检、pair 关系核验、完整 Preview/business/canonical、census 和最终发布暂维持既定执行方式。正式产品计时、产品线程 N、同节点整机单飞及冻结测量口径不变，不把多个计时场景放在同节点并跑，也不以 05 诊断时间代替 CT108 正式基准。以后是否并行独立验收，须先确认共享状态、峰值预算与可比性，不在本轮顺带扩大。

05 空闲且原子取得占用后，在 clean 已提交候选上做有界定向验证：公开 CLI 的 1/2/4 路生成结果与完整报告等价、真实独立重复、上限为 N、失败/硬退出收束及不发布未完成记录、成功分段复用、验收失败不发布 READY。沿用已有不变量测试，避免为调度复制算法断言。五包 Ruff/mypy 仍执行，不重跑全量产品 runner。另可用已有有界真实 SQL 样本，对新 pair/W4 调度做相同输入、相同工作量的 2/4 路诊断，各一次、总上限 15 分钟，记录输入身份、墙钟、聚合 RSS 与输出摘要；不足以计算稳定加速比时如实报告。每次诊断结束清理进程并释放本次占用。

不为展示新 CLI 再做一次 full4 大生成。已有全尺寸四路 W4 结果只支撑 W4 的观测资源范围，不证明新 pair 并发峰值；下一次确有必要的大输入准备须单列 pair/W4 预算，并在启动前核对缓存、CPU、内存、磁盘与进程收束方式，沿用全量诊断的运行期资源/截止停止原则。候选、focused/静态及有界诊断记录交原审核者核对，通过后由基准实施者协调合入与后续启用；设计不判实施证据。
