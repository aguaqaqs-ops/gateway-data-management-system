# Preview 临时性能优化总计划与分包

2026-11-13。依据 Owner 要求，先形成总计划和可独立推进的分计划，以有限普通真实数据对比定性选择方向，不建设大量合成负载或多次统计矩阵。本次仅记录计划，不启动产品实施、补测或部署。分析依据见[publication 方案](preview-publication-options.md)、[业务表并行方向](preview-business-parallelism-notes.md)及[第二轮实测](/home/dev/gdds-stage-exchange/gw08-preview-bundle-measurement-sol/round2/REPORT.md)。新的 publication 语义取舍尚待针对性独审，前次热点设计审核不自动覆盖它们。

## 1. 目标与边界

目标是用可控成本回答：哪些重复工作值得删除、哪个最小改动能让普通 t4 Preview 明显变快，同时保持用户看到的比较结果、可重新下载的持久 Preview 和后续 Submit 绑定正确。先定性判断，不承诺性能达标、百分比收益、跨设备稳定性或完整容量认证。

正确性修复前普通 MO 的参考窗口为 materialize 36.532 秒、assemble 96.233 秒、publish 6.602 秒；其中 bundle 40.535 秒内 publication 加即时读回 28.463 秒。父子计时不相加，28.463 秒不是可省时间。旧 FULL baseline 为已归档 v1 的 81 秒记录不作为当前空 INITIAL FULL 对照。

默认保持 N1/M24、现有资源配置、异步 API、流式 tar 和前端 OPFS；不改 control DB/Dolt 权威事务或取消 READY 前最终完整校验。完全内存 Preview、降低持久性、提高 N、表内切分和通用调度池不在首轮实施范围。业务表并行保留为后续候选，只有去除重复工作后仍有已证表级热点才另开实施包。

工作留在当前临时分支体系的独立候选 worktree，不改 main、不推送、不部署 08、不覆盖他人前端文档；测试在合格空闲专用节点、clean 已提交树和离线缓存下执行。同组前后对比留在同节点同资源。优先复用 05 的合法输入/依赖/工具，现场重新核占用与服务，不预留空占。

本工作在[比较正确性与审核结果复用修复](comparison-correctness-repair-implementation-plan.md) A–D 完成并通过约定必要验收后启动。P0 核收修复最终提交、规则/审计/保护变更和证据，冻结未优化基点 B0；必要的纯观测提交记为 B1。P1 采集修复后普通 MO 新基线并重排热点，P4 完成修复后 FULL 基线与最终候选对照。采集、有限插桩和汇总均属于本工作，不另立补测项目；Owner 完成修复后可直接按本文及[详细方案 §1](preview-optimization-implementation-plan.md#1-本轮交付与技术边界)实施。

新基线必须包含修复后的 12 类行比较、结构判等/后台审计和提交保护语义。历史样本仅供定位，不能将修复前基线与修复后候选作提速对照。若新热点已变化，交付基线和下一方向建议，跳过不适用 P2/P3；不自动启动 R1–R4。修复进行期间只可准备脚本/清单，不并行修改重叠产品路径或采集旧语义作为新基线。

## 2. 总体顺序与分计划

```text
正确性修复 A–D 完成并通过必要验收
  → P0 单个 Terra high 子 agent 核收交接、冻结 B0，核范围与关键约束
  → P1 同一 Terra 采集一次修复后 MO 新基线并汇总热点，不另设独审
  → 选中实际优化后才启用 Sol 实施者
  → P2 即时读回合并的最小候选（仅值得时）
  → P3 不变成员直接引用（重点；需要时以基线而非P2为父）
  → P4 修复后 FULL 基线与最终候选对照，消费者小范围核对，收尾

P1～P3发现的新线索 → 其他阶段候选清单；不自动开启额外测量/实现
```

每包由协调者给出继续、改选或收口决定；已授权范围内的常规命令、缓存准备和可逆细节不反复请 Owner 确认。改变业务保证、Contract适用范围、N/M或动他人资源时才提交明确取舍。

| 包 | 要回答的问题与产出 | 最小验证与退出条件 | 主动工作预算（规划上限） |
| --- | --- | --- | --- |
| P0 交接与范围核对 | 单个 Terra high 子 agent 核收修复最终提交与已有验收，冻结 B0；盘点新规则/审计/保护与测量范围 | 直接引用已有验收，不重新审核修复；测量前提齐备。优化语义先作初步判断，选中优化后由 Sol 细化 | 30–45 分钟 |
| P1 修复后新基线与热点复核 | 同一 Terra 复用脚本，必要时补局部计时/计数；采集 B0/B1 的 MO，核对新语义结果、记录原件并汇总热点 | 普通 t4、空 INITIAL 一次；不单独安排 Astra/Luna 或 Sol，不重复读 payload、预探 exists 或解析 SQL。观测改动只做相称的必要检查，不为基线重跑全量验收；改变行为则按实际风险处理 | 30–45 分钟；运行准备另见总预算 |
| P2 合并即时读回（条件项） | 若P1显示有值得删除的重复工作，且实施前确认final覆盖，则删逐件即时readback，保原final完整验、错误拒绝和READY顺序；不顺带改store、同步或publish闭包 | bundle既有正常/嵌套ref、错误put/损坏、destination失败、取消/M边界focused。候选MO一次，与P1同口径比父段和删除的读次数；收益不清且代码不更简单则不保留，不为证明小收益加跑 | 45–75 分钟；无价值可直接跳过 |
| P3 逻辑bundle复用（重点） | 同store内合法未变成员保原ref，避免无意义重ID/复制；只写真正新成员及必要surface/manifest/closure。递归引用、shared/table_bindings、保护和跨root下载闭合；跨独立destination仍复制并验目标 | 同一业务目标实现，删除被替代路径，不保永久双算法。更新实际受影响Contract/golden；focused验证混合root、共享引用、必要rewrite和清理保护。候选MO一次，比较新写数量/字节、publication及端到端。若P2保留则比较增量，否则从原基线建候选，不拿不同父实现混算 | 90–150 分钟；若需新artifact生命周期框架则停止扩展并收口 |
| P4 最终消费者与收尾 | 选择一个候选；确认普通FULL两pair、下载/OPFS及Submit引用保护仍成立，写清收益和遗留项 | Terra 采集尚缺的修复后 B0/B1 FULL 基线，再交接同节点由实施 A 测最终候选；各一次普通t4 FULL，均空INITIAL、同节点同配置；已有本轮合格同条件样本可直接复用。复用focused/Contract验证恢复/Submit保护；必要时利用本次候选数据做一次下载/浏览或Submit烟测，不重跑整旅程。实际改动触发的必要门禁按仓库规则集中运行，不称诊断等于发布验收 | 45–75 分钟，门禁时间单列 |

新基线采集是本工作必需部分；正确性验收中已有同版本、同输入/节点/资源/应用状态及完整计时身份的样本才可核实复用。P1不是无限profiling前置：只做这组能改变方案选择的计数与互斥计时。若修复后源码与合格新基线原件已足以选C，P1的细计时可与最小A/C前后对照共用，不另起一份只为“补完整”的真实运行。P2也不是P3的必经门槛；优先解决实际冗余最大的工作。

P3要先从已允许的成员类别切入，不能把“同hash”当跨repository授权，也不能用source可读代替独立destination可读。合法不可变引用移交不等于暴露cache-local/host路径。若确需由Owner统一Contract类别，P0提供具体文字和效果再决定，不泛化成是否允许优化的空泛确认。

## 3. 有限对比预算与定性判据

本轮真实 Preview 默认最多 **5 次**：P1修复后基线MO一次，P2候选MO一次（可跳），P3候选MO一次，P4修复后基线/最终FULL各一次。FULL基线如选型确需可前移P1，P4不再重复；不另增加“重建基线”次数。共用或跳过的样本不“补满”。仅当唯一关键比较被明确环境干扰或证据矛盾影响时允许 **1 次**针对性补跑；累计最多6次真实Preview尝试，失败尝试也计入，不循环找最好值。消耗完则保留“未知/不值得”，不自动扩预算。工具环境修复沿AGENTS现行规则处理，但不得用修复名义重跑被测对象而隐去失败。

- 数据只用已有普通t4 v1/v2；不生成2×t4、压力放大或大量合成表。小型正确性fixture复用原owner，只补真正改变的边界，不做性能合成矩阵。
- 不固定预热加三测，不估p95/置信区间，不扫描并发度/缓存组合。每个选中版本同一形状默认一次；不把独立采样的均值/最好值当稳定性能。
- 固定baseline（空INITIAL）、源码/扩展/锁/输入、CPU/M、同节点、存储路径类型与fresh应用状态；OS/page cache不清就明确记录。两个版本尽量相邻运行，不混其他任务；不能宣称物理硬件或page cache完全无干扰。
- 先看操作计数是否实质减少：少写多少真正副本、少读多少遍、所选父段是否同方向缩短；再看受理至结果可读。单次端到端变化小或与热点指标矛盾时判“收益未证”，不追加一串测试找显著性。不能把相互覆盖的收益相加。
- 保留条件：业务/恢复/引用保护检查通过，M/CPU配置未放宽；减少的操作与预期一致，阶段耗时支持方向，且代码/状态复杂度可接受。结构更简单但耗时差异不清时可记“简化有效、性能未知”，不能称明显提速。
- 不保留条件：输出/保护或资源失败，或仅移动成本到下载/Submit，或新增复杂生命周期而收益不明。已发现正确性问题先修正/排除，再谈性能；测试范围小不降低正确性要求。
- 前端可见尾段尚未测。P3涉及交付成员时P4做一次代表性真实浏览检查即可，不以后端READY变快宣称用户首屏必然同比变快。修改前端代码前仍按仓库规则协调前端owner。

目标为一轮约 **4–6小时主动实施/分析时间**；真实Preview累计运行预留 **30分钟以内**，正常离线准备/构建/必要focused预留 **60–90分钟**，具体取决于节点缓存与改动。均是工作量预算，不是性能承诺，也不修改产品lease/timeout/取消行为。异常耗时或达到6小时仍未闭合时先记录当前可用结论和阻塞，不为赶预算弱化校验、强杀他人服务或扩大实现；后续按实际价值另排。节点排队、缓存补齐与最终必要门禁耗时单列，现场超出预估及时报告。

## 4. 其他阶段的后续候选

以下是分计划储备，不是首轮自动执行列表。P4后根据剩余耗时最多选一个新包；其工作与对比预算另行明确，不从publication推断所有store consumer都能同等提速。

| 后续包 | 进入条件 | 最小工作 |
| --- | --- | --- |
| R1 物化/导出复用 | publication优化后仍有显著materialize/export窗口，且源码能指明重复encode/lookup/validate/put | 先复用已有cache/reader与完整内容键，选择一个明确调用点，必要时一次受影响普通t4对照；不全层重构 |
| R2 checkpoint恢复或publish闭包 | 已识别同一保护范围的重复decode/精确ref核对，或剩余窗口确实主导 | 保持durable恢复和CAS单一语义，仅同handler短scope复用；不建跨step活reader/verified持久状态机 |
| R3 业务表专用并行 | 一类表仍有已证CPU/独立任务热点、完整实例/行数已盘点，且单表/多表偏斜明确 | 完成安全owned输入/输出、M和取消协议，再在明确获准N档小试；当前N1不自动扩核，不建通用调度池 |
| R4 前端加载尾段 | 后端结果已可读但用户仍明显等待，已有浏览证据定位下载/OPFS/解析 | 一条代表性浏览旅程区分传输/安装/解析，优先利用已有digest本地复用；不先改为全新分页API |

## 5. 角色、记录与退出

基线 P0/P1 由一个 `gpt-6.1-terra` high 子 agent 独立完成交接核对、必要局部观测、测量和报告，不启动 Sol、Luna 或 Astra，也不安排单独审核。FULL 基线若延后至 P4，仍由 Terra 完成并交接同节点给候选执行者；基本身份、资源、结果和失败留证检查保留。可直接使用的委派说明见[详细方案 §1.3](preview-optimization-implementation-plan.md#13-基线阶段单个-terra-high-子-agent-完成)。

进入实际优化后，采用 Owner 最新确认的分配：`gpt-6.1-terra` high 协调，A/B 两名 `gpt-6.2-sol` high 实施者分别负责 publication 优化和消费者适配，以及各自的测试代码/运行脚本。既有门禁和最小脚本在两节点执行测试，不设置专职测试 agent。`gpt-6-luna` medium 仅按需核对证据清单；确定性结果已足够时不启用。失败归因、测试范围及重跑由 Terra 判断，不交脚本或 Luna 自行决定。

`gpt-6-astra` high 默认在最终代码、测量和必要验证结果齐备后，以新上下文集中分析与独审；实际 A/B 类边界仍按仓库规则提前逐包独审。finding 原作者修复、原审复核，不为日常命令或每个计时样本另建审核轮次。

具体职责、文件归属、节点安排、交接与退出条件见[详细实施方案](preview-optimization-implementation-plan.md)。基线仅一个 Terra 子 agent；优化阶段通常三个活跃 agent，核证与独审错峰增加至四个；两节点脚本不占 agent 槽位，不需要增加到六槽位。当前只是文档分配，未启动实施或切换当前会话模型。风险和必要门禁遵循 [AGENTS](../../AGENTS.md) 与[比例化政策](refactoring/formal/policies/proportional-assurance-and-risk-based-verification-policy.md)，定性实验不冒充发布验收。

临时插桩保持在隔离诊断候选，只保留解释所选问题的有限计数；获选优化形成清晰产品diff，删除已不需要的实验代码，不将临时instrumentation整包带入正式主线。旧成功/失败日志及各轮原件保持不动。每个小包只有一份简短结论：改变什么、同条件输入/版本、实际次数、操作数量和耗时变化、正确性验证、未知、保留或放弃；机器身份/exit/SHA由外置证据承接。

过程与对比原件统一放仓库外 `/home/dev/gdds-stage-exchange/gw08-preview-optimization/`。结束交付：选择的最小实现/设计、两种普通输入的有限证据、未测/放弃项、后续最高价值一项。若无需进一步优化即收口，不自动启用R1–R4；若核心结果仍不确定，明确“不足以判断”而不追加大量数据或重复运行。
