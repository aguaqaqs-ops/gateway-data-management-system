## 1. 目标与阶段边界

现有合成数据不足以代表真实业务分布。本轮建设单机、有界、可配置的多设备库处理能力，以少量已有真实数据选择保守默认值并准备受控试运行。外部系统陆续输入真实历史数据，本系统记录处理结果、异常、存储和资源消耗，后续据此独立校准吞吐、延迟和容量。

本轮完成：多 worker 正确性与恢复、同机独立处理组、交互和批量调度、准入背压、按类型挂载、设备库占用统计、逐任务基础资源观测、只读统计接口、外部历史回灌接入、设备全状态测试副本及试运行操作说明。

本轮不承诺线性扩展、1,000/10,000 仓库已验收或长期 p95/积压消退目标；不建设多机执行、网络文件系统、对象存储、自动扩缩容、冷热迁移、按容量淘汰平台、历史排序器、精确费用分摊或独立监控服务。内存带宽和逐 commit 独占块分析为后续按需事项。

P6 已正式退出，P7 不调整 P6-S6 退出条件或结果。实施入口以 `p6-exit` 的 `b0fc25e881cb4ce39b1cc847bad92b4ccb06b809` 为祖先，在实际 main 后继上复核代码和测量。P8/P9 的生产接入与长期运维责任保留；本轮所需恢复、暂停、排空、数据重建和查询能力不能延期到上线之后。

## 3. 单机部署与设备映射

### 3.1 部署

每个处理组沿用 backend、worker、Repository Service、control DB 与本地 artifact 的部署结构。组内 worker 可多个，每个进程维持一个 active executor；不引入通用 DAG 或将单 operation 内的表任务分散到多个 worker。同组 worker 共享本组 control DB 与所需数据卷；不同组拥有独立 backend/RS 状态、roots 与 worker 池，不共享全局业务 control DB。分组用于静态分担负载和构造独立环境，不建设在线跨组自动均衡器。

轻量共享目录只维护 `(environment_id, external_device_id) → group_id`、有效状态及变更版本；组内仍权威维护设备到 repository 的业务映射。业务任务、审核、租约、effect 和 artifact 保护均留在组内。首版生产换组须停投递、排空并查明未知 effect 后转交唯一写入责任；静态目录不承担分布式锁或跨组事务。

阶段安排已由 Owner 确认：S1a 单组单 worker 存储/资源及环境组标识；S1b 统计携带环境/组归属；S2a 组内多 worker；S2b 独立组/静态目录；S3 组内公平与整机预算；S4a 映射/回灌；S4b 设备抽取/加载与受控换组；S5 综合验收。细节见[分组与测试副本设计](p7-processing-groups-and-test-extraction-design.md)。

测试抽取默认复制所选设备全部现存历史、审核、未完成任务及其必要依赖；一致捕获后在独立可写环境按原恢复规则加载，不要求先完成所有 pending 任务。源/副本的凭据、端点、卷、领取范围隔离；没有历史选择器、双向同步或回合并。测试副本不能直接接回生产取得写入权，跨版本兼容也不是本轮承诺。

沿用可信内网、受控部署、单组织信任域。外部展示是经现有认证授权的只读客户端，不等于公网匿名接口。所有测试仍按 AGENTS 在专用测试节点执行；实际试运行实例的部署另行授权。

### 3.2 映射单一权威

复用 `provisioned_scope_mappings` 及既有初始化／scope 校验。本系统权威维护外部设备到 repository 的绑定，外部仅缓存查询结果；不允许双方独立编辑后自动合并。提供有权限的注册／查询／禁用和导出核对边界，具体适配在 S4 完成，不要求新建设备主数据平台。

现有实现还限制一个设备只有一个 enabled scope、一个 repository 只有一个 scope，并校验 INITIAL 节点归属；注册和重放必须保留这些约束。映射一经关联实际业务记录，不能通过普通导入或 seed 更新静默改绑。设备合并、拆分和已有库重新归属不在本轮自动流程内。

外部标识以不透明标识处理，先复用现有字段。多个来源确有需要时使用明确来源命名空间；不截断、不有损清洗、不直接作为路径。超过现有边界时在适配层给出明确错误或显式无损映射，不能偷偷产生新设备。

清库重建后外部重新查询或注册映射；旧 repository/operation ID 不保证跨重建有效。跨轮比较以外部设备、版本及运行批次关联。未知、禁用、冲突返回可区分结果；按需核对足够，周期自动对账不作为本轮前置。

## 4. 外部历史回灌

### 4.1 输入与顺序

外部系统发现文件、解析历史、确定设备和版本顺序，再按业务顺序输入。本系统不扫描外部档案、猜版本或按数据生成时间重排；原始时间和来源保留供现有规则诊断。

接入信息至少关联外部设备、稳定版本标识、顺序或前驱版本引用、导入批次、输入模式、内容指纹及幂等标识。初版通过外部有序投递及现有基线预期校验保证衔接，不预建持久历史 DAG 或全量排队清单。具体字段、长度和错误 DTO 在 S4 定稿。

输入继续遵循 FULL／MODIFIED_ONLY Contract。FULL 必须具有真实 initial/modified 角色，MODIFIED_ONLY 明确复用基线；不能把缺少 initial 的输入冒称 FULL，也不能伪造 initial 来通过来源核验。首次空基线走现有 INITIAL 规则。

同一设备前一版本归档完成或明确 `NO_CANONICAL_CHANGE` 后，才投递下一正式版本；仅收到 HTTP 受理响应不代表完成。不同设备可并行。调用方遇到结果丢失先查已有结果或用同键重放；不得用新键盲目重提来推进顺序。

外部同版本同输入重试沿用已有结果；同版本对应不同输入需明确冲突。传输/业务重试与显式性能复测分开，复测记录新的执行尝试但不制造重复业务提交。无规范变化记录为无变化结果，不要求每个外部版本都有 Dolt commit。

影响幂等判定的外部版本关联必须绑定现有业务结果，不能以可丢弃的统计摘要判断“已经提交”。这种关联属于可恢复业务执行状态，和限期资源曲线分别保留。无变化不是异常豁免：已发现的时间、来源或身份异常仍保留并按停链策略处理，不能被 `NO_CANONICAL_CHANGE` 覆盖。

### 4.2 自动处理与异常停链

专用回灌客户端使用现有身份和权限模型，显式标识程序 actor 和回灌用途；不是新 OS 安全主体。它调用正常业务入口执行审核通过、归档选择确认和归档，不直接写 control DB 或 Repository `main`，不提供跳过校验的服务端开关。业务元数据表达程序执行，不冒充人工判断。

归档相关异常可能只有在 Submit 或 Review 后才能完整发现。因此客户端逐步执行并按最新状态检查；发现异常后停止进一步推进，保留已成立的 Submission/APPROVED 等真实状态，不能把已提交结果伪装成全部回滚。

| 结果或事件 | 回灌处理 | 基线与后续 |
| --- | --- | --- |
| 全部适用检查通过 | 程序按既有权限完成审核、确认和归档 | 精确绑定新 Head 后处理下一版本 |
| 无规范变化且无待处理异常 | 记录输入、观测及无变化结论 | 不造提交；使用未变 Head 继续 |
| 需要人工决定的来源、时间、身份等异常 | 保留诊断、相关业务状态和引用；不自动接受、不伪造原因 | 停止该设备基线推进；其他设备继续 |
| 后续版本可独立分析 | 显式样本分析，绑定实际提供的比较对象；必要时使用独立测试环境 | 不加入正式历史链，不当成归档成功 |
| 后续版本缺少必要比较输入 | 记录依赖阻塞及原因 | 不制造缺失基线，不静默换比较对象 |
| transient I/O／资源拒绝／worker 中断 | 沿现有有界重试、恢复和查询机制处理 | 不跳过未定写入结果继续下一版本 |
| 损坏、授权失败、scope 冲突或映射冲突 | 明确失败，保留必要诊断 | 不豁免、不自动改绑 |

既有 PENDING、active Attempt、Workspace 占用和 candidate-set 门禁不绕过。样本分析不能依赖强行释放被阻塞提交的 Workspace；S4 确定复用现有独立 Workspace/测试路径所需的最小接线。恢复正式链必须先通过既有业务处置和新 Head 核对，不因重启导入程序自动视异常已解决。

本轮自动化范围不包含人工接受异常或自动关闭问题提交。若后续要求，须单独明确允许类别和审计语义。

## 5. 资源预算与多 worker 生命周期

参数含义：W 为 worker 进程数，K 为整机允许同时执行的 executor 数，N 为单 worker kernel 线程配置，M 为 kernel 准入预算，E 为单 worker 内存 envelope。每个 worker 最多一个 executor，K ≤ W；N/M 不等于测试 worker 数。

同规格 worker 的保守内存规划至少覆盖 W × E、backend/RS/Dolt/control DB、OS/page cache 与必要余量；M 只是 E 内的计算准入预算，不是 RSS 硬上限，不能仅以 K × M 判断整机容量。CPU 预算同时考虑 kernel、Arrow、RS 和其他服务，磁盘/I/O 独立观察，不承诺 K × N 能解释全部线程消耗。

S1 统一应用配置与 Compose/container 限制，校验正值、上限、M 与 E/reserve、K 与 W 的一致性。单机默认静态配置，不自动调参；改变配置先排空／重启。当前代码中的固定预算不是未来全部开放的参数，租约、心跳和事务期限保持 Contract 约束。

S2 修改 startup 对其他健康 worker 租约的判定，区分存活持有者、过期接管和未知 effect。原子 claim、lease token/CAS、迟到写入拒绝、同 repository writer 互斥、effect 后先核结果再恢复均保留。某 worker 的 OOM/native crash 不得授权另一个 worker重复提交，也不得误判全部活跃任务应恢复。

K 先可由受控 worker 数实现；若 W > K，必须有原子且可恢复的槽位约束，不能依赖进程内计数。选型在 S2 定稿，优先复用现有事务，不为槽位另建服务。休眠 worker 的常驻内存仍纳入规划。

## 6. 调度、准入与期限

在现有持久 operation/step 队列上实施交互优先与批量保底，按设备库避免单库长期独占。S3 确定简单的领取策略、保底/aging 参数和有界验证，不建设通用任务调度平台。优先级只作用于可领取任务，不抢占运行中的事务或提交；保底不是不受任务时长影响的完成时限承诺。

上传接收、已受理队列、executor、RS 请求和单库写入分别有界。上传过程中占用的接收名额不能当作执行槽位，RS 等待也不能通过无限线程／重试扩张。正式回灌顺序由 §4 约束，不通过队列优先级重排同设备历史。

区分接收超时、排队等待期限、实际执行期限与恢复期限。排队不偷偷消耗本应从执行开始的预算，也不默认改变现有绝对业务 deadline；S3 修订 owning Contract 后接线。未终结的有效任务所需输入、checkpoint 和 READY closure 必须被保护，不能因长队列超过缓存 TTL 而丢失。

暂停批量停止后续投递/领取，当前任务正常完成或沿既有取消/drain 退出。取消、过期和重试有明确结果，不自动强杀事务。只读状态查询在允许的生命周期阶段继续可用。前端显示排队/运行/阻塞原因；没有足够数据时不承诺精确排队位置或 ETA。

## 7. 存储类别与本地挂载

| 逻辑类别 | 数据范围 | 保护与清理 |
| --- | --- | --- |
| repository | Dolt 库 | RS 独占管理写入与 GC |
| durable artifact | 原始上传、Submit 必要输入及其他需保留产物 | 现有业务 owner／有效期，不因可重建一律删 |
| canonical table | 规范表与物化输出（当前 Arrow IPC） | Head、Preview、Attempt 等保护与现有 TTL |
| comparison cache | diff/risk 及对应产物 | 以实际引用/closure/TTL 为准 |
| export cache | Parquet 导出、可重建交付缓存 | READY 所需引用与缓存保护分开 |
| scratch | 工作临时文件 | 有界、协作清理，不包含唯一恢复依据 |
| metadata/telemetry | control DB、RS 元数据、统计摘要与有界观测记录 | 角色分别定义，不与缓存清理混用 |

类别表示物理存储责任，不只按扩展名推断；一个产物可有多个用途和多个保护 owner，但其物理对象只记在一个存储位置。同一类型可配置不同本地挂载位置，默认同盘；本轮不实现每设备任意选盘、自动迁移或跨类别动态挪动。

保留与物理路径无关的四字段 ArtifactRef；S1a 的新 ID 显式编码组内逻辑位置，绝对路径只存在部署配置和存储 adapter。S1a 定稿多 root 定位机制及所有 put/locate/stream/cleanup 消费者，使用明确逻辑位置，不扫描全部 root 猜位置。若必须改变引用载荷，直接按目标形态改 owning Contract 和消费者，不加旧格式双读层。

写入的发布 staging 必须与目标处于同一文件系统；独立 scratch 输出需受控复制至目标 staging、完成既有校验/持久化后发布，不能把跨盘 rename 当作可行原子操作。挂载变化后 worker、backend 和 cleanup 对位置的理解一致；缺挂载/不可写明确拒绝，不自动回退系统盘。

按实际 filesystem 去重计算可用容量，不累加同盘多个目录的 free bytes。磁盘低水位限制受影响的新接收/领取并保留运行余量；容量检查不能保证之后绝无 ENOSPC，实际写满仍须安全失败且不发布残缺结果。本轮不通过按容量删除受保护产物解压。

## 8. 设备库占用与提交增量

### 8.1 统计口径

每设备库按类别记录对象数、逻辑字节、可用时的 filesystem allocated bytes、受保护／未保护状态、测量时点与完整性。项目引用量与去重后的物理量分开；共享对象列出共享归属，不把多次引用相加冒充真实占用。用途分类可重叠，物理分类总量不可重复计数。

组级 metadata、共享对象、临时文件、未归属对象单列，不强行均摊给设备；环境/组标识贯穿 S1b 摘要及查询，跨组/测试副本是真实额外占用，不能按相同 artifact ID/SHA 跨环境去重。整机汇总按实际 filesystem 计容量，组内共享引用另计逻辑量。平台 thin pool、快照、压缩/去重成本属于宿主存储统计，不能用 guest allocated bytes冒称已测。低频缓存不得因长时间无访问失去当前 Head 保护。

基础对象大小优先复用现有 artifact/cache 元数据；物理扫描有界、分批、注明窗口，可异步核对。不在每个 HTTP 查询或数据库写事务内遍历全盘，不为了精确观测阻塞整个提交服务。丢失/孤立文件核对与 cleanup 各自负责，统计发现不直接授权删除。

### 8.2 每次 repository 写入的观测

测量起点在本次导入写入之前，而不是仅包住 `dolt commit`。记录写入前与提交后观测、repository/submission/前后 commit、窗口、失败/成功、其他写入或维护干扰和测量完整性；样本不完整时不填零或伪造差值。

`after − before` 是窗口内观测净变化，不是该版本独占物理成本。Dolt 结构共享、垃圾及维护使差值可能小于零；GC 前后单列记录，不为统计每次提交都执行 GC。异步后测若窗口混入下一写入，明确标记，不能称为精确单提交增量。不能取得无干扰窗口时报告受限数据，专项串行回放再归因。

失败尝试留下的空间也需可见；提交增长、临时峰值和清理后状态分列。聚合与明细可重建，观测失败不撤销已成功提交。

## 9. 每次上传与任务资源观测

沿外部批次/版本、upload、operation、attempt、submission 关联阶段，而非把整个上传到归档视为一个不可分指标。分开记录传输、排队、Preview、Submit/finalize、归档和后续分析；外部预处理耗时不混入本系统执行耗时。

| 指标 | 本轮口径 |
| --- | --- |
| CPU | 可归属进程/cgroup 窗口的 CPU 时间及平均使用核数；标注窗口、限流和计数重置 |
| 内存 | 窗口采样峰值、进程与容器范围、匿名/page cache 等可用分项；标注采样间隔 |
| I/O | 可用的读写字节、操作数、平均速率和采样峰值；标注设备、缓存写回及共享范围 |
| 存储 | 产物逻辑字节、repository 净变化、scratch 采样峰值 |
| 结果 | 成功、无变化、异常停链、依赖阻塞、取消、资源拒绝及失败；所有尝试可追踪 |

直接业务计数、worker 执行窗口、共享 RS/宿主观测分别表达。单 executor 的 worker 窗口仍可能包含常驻缓存/后台开销；不把 RSS 当作任务新增内存，也不对进程生命周期峰值做差冒充本次峰值。多个任务并发时整机/RS 差值不独占归给一个上传，不能把不同时间各进程峰值相加声称同时峰值。

复用标准进程/cgroup 观测能力，采样本身有界；不为了统计给业务服务增加特权。缺少计数器或权限时标为 unavailable，说明范围。内存带宽需实际宿主硬件支持和专项测量，不作为当前容器内逐任务必选项。

每条摘要关联程序版本、规则/输入身份、有效资源配置、硬件/存储类别描述、冷暖条件及观测来源。统计摘要和有界曲线属于运行诊断，非不可变计费账本；采集失败不得改变业务结果。采用逐尝试摘要＋限期高频曲线＋有界存储，S1b 给出默认保留/采样/容量配置，S5 核实际开销。

## 10. 只读统计接口

在现有 backend application/query 与 HTTP 边界内提供稳定查询模型，服务内部运维、导出和未来外部展示，不增独立服务。首版覆盖设备库分类占用/趋势、逐提交净变化、逐任务摘要/异常，以及有权限的共享服务观测。

API 采用显式版本、bounded 分页与时间范围。返回统计单位、scope、采集窗口、freshness、完整性和缺失原因；缺失不等于零。来源字段区分直接统计、执行窗口、共享观测，不把估算冒充测量。

设备级查询按 repository scope 授权；全局磁盘、配置和共享服务数据仅限合适的运维权限。复用现有认证机制，S1b 定稿只读权限/DTO 和 OpenAPI，S4 接外部 consumer。调用方不能任意选择服务器路径，响应不泄漏绝对路径、凭据或原始业务 payload。

查询基于已生成记录，不能触发全盘扫描、重新计算业务结果、GC 或设置修改。详细任务 ID 留在查询/摘要记录，不要求把它们变成无限增长的监控时序标签。首版轮询和导出足够，不承诺实时推送和专用可视化大屏。

## 11. 可重建试运行与保留

原始输入在外部持久保留，本轮允许人工受控清空后重建；这不削弱运行中的提交一致性、身份、幂等和权限约束，也不授权自动删库。重建会丢失本轮 ID、审核/异常处置、缓存、采样曲线等，不能称为原状态恢复。

仍采用单一基线 schema。提供停投递、排空、统计/异常导出、受控重建、映射重新注册和恢复导入说明；不为本轮构建通用备份平台或兼容迁移层。需要跨轮保留的摘要可导出至环境外，保留期限与曲线容量由配置管理。

首次承诺保留正式业务状态、原始数据不再可重放或引入真实人工审核保留责任时，重开部署和数据生命周期设计，补齐必要前向 migration、备份恢复及恢复目标后再采用新承诺。

## 12. 风险与验证 owner

遵守 [比例化保障政策](../policies/proportional-assurance-and-risk-based-verification-policy.md) 与 [ADR 0012](../adr/0012-cooperative-artifact-cleanup-and-proportional-assurance.md)。

| 类别 | 对象与实际风险 | 最小保障和验证 owner |
| --- | --- | --- |
| A | 设备归属、跨 scope 写入、Dolt commit/Head、审核归档事实 | 映射唯一性、鉴权、CAS/事务/幂等；领域/RS 现有 owner |

## 14. 本轮退出与后续校准

本轮退出要求：适用并行/串行正式结果与 digest 一致；映射/写入/租约/恢复屏障正确；按类型挂载、跨 filesystem 发布及保护清理正确；队列、CPU/内存配置、上传和磁盘使用有界；设备与任务统计有可解释口径；自动回灌正常、无变化、异常停链和样本路径通过；默认配置及适用硬件/输入范围有依据；试运行操作和只读接口交付；最终权威及容器门禁按执行计划完成。

缓存 miss/corruption 不改变业务事实；仍被任务/READY 强保护的 artifact 丢失不能被泛称为可忽略 cache miss。资源拒绝是明确功能结果，不作为该负载成功处理或容量达标证据。

观察 1、2、4、K 个设备的实际可运行档位，不为凑档位超出资源；并发正确性至少覆盖两个 worker，生产默认可以更保守。报告耗时、队列、吞吐、内存/I/O/存储和失败，未知不记通过。本轮不验收未经真实分布校准的长期性能承诺。

后续校准由主要业务类型、大表分布和高变更比例覆盖，或持续积压、资源拒绝、磁盘增长等实际问题触发；不只按累计输入数量。采用真实输入回放并分别构造到达节奏，历史数据代表性不等于用户到达分布。合成数据继续覆盖极端边界和故障，不承担主要生产容量推断。
