实施起点的 `_generate_pair` 确实先生成并封包 2×，核对已接受身份和 Preview，再处理 W4、census、summary 数据及 SQL/package 重复生成，最后写 `input-summary.json`；`prepare_inputs` 拒绝已有输出根。kickoff 对返工成本的描述有代码依据，但本次没有测量各段耗时，不量化预期节省。

现有管线不仅生成文件，还保留 v1/v2 2× 未变化副本关系检查、输入清单与 census 的 dataset 集合一致、ordered census 完整性、全表 Preview 零诊断等检查。§1“不改变正式验收条件”及 §4“完整验收不取消”涵盖这些内容；分段时应保留原检查的语义与依赖，不能把“文件摘要相同”当成所有检查均已通过。具体函数归属和结果清单留待实施候选审核，不在本报告新增通用恢复协议。

复用生成物与复用验证结论是两件事。尤其重复生成的证据必须能指向独立生成动作和相应输入/实现，不能在复用命中时把同一份文件复制成两份后新写“确定性通过”。历史验证记录缺少必要身份时按 kickoff 拒绝复用或重做相应检查，不补造历史事实。

## 3. 非阻塞澄清建议——交设计会话

1. **把空字符串键写入预检覆盖清单。** §3 已有“可空键、空表和字符串默认值”，但 SQL NULL、空字符串键与普通字符串默认值是不同情况。建议显式写明已发生 KEY_EMPTY 的键默认值路径，并在覆盖记录中对应到实际表形态及非零插入配额。保留现有回归即可，不要求同一不变量重复建多套测试。该建议具体化已有真实表形态覆盖要求，不增加全量验收。
2. **依赖表显式列出继承的 manifest/census。** 现有工具以 `datasets.json` 定义 dataset 集合，以 `baseline_census` 合并未重算项。建议实施 handoff 的依赖/失效表将二者及其来源身份归入相应输出和验收步骤；变更时重算受影响清单/验收，不必无条件重生成所有 SQL。§4 的相关输入和保守依赖范围已要求这一点，显式列出可防止实现只摘要 SQL、规则与生成函数而遗漏继承记录。

这两项不阻塞既有授权下的实施。由 owner 转交设计会话处理，审核会话不修改 kickoff/DC/执行计划正文，也不直接通信。
