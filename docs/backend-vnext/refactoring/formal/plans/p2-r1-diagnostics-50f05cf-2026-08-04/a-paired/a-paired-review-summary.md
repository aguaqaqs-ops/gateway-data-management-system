## Paired interpretation

- **DEVNULL 没有消除规模增长。** 以 256 bound 的 middle window 为例，DEVNULL provider delta median 从 S10 的 150,308 KiB 增至 S40 的 188,172 KiB、S100 的 259,776 KiB；对应 cgroup delta median 为 56,410,112、96,460,800、178,614,272 bytes。1024 bound 也呈相同方向。
- **更接近 Dolt CLI/query 侧，而非 Arrow serialization。** streaming 的 Arrow plateau 基本固定在 124,544 bytes；DEVNULL 不经过 Arrow，Arrow plateau 为 0，但 provider/cgroup 仍出现规模增长。该诊断支持“Dolt CLI/query 或其进程工作集”方向，但不构成正式因果证明。
- **RssAnon 是 direct DEVNULL 中主要随规模变化的分量。** 256 bound 的 provider RssAnon median 为 S10 68,172 KiB、S40 114,804 KiB、S100 203,016 KiB；RssFile median 约稳定在 103,604 KiB。streaming 路径没有同口径 RssAnon/RssFile 字段，不能补造分解。
- **窗口不可直接横向比较。** streaming 的 first/middle/final 是 row-window；DEVNULL 是 command-duration time-window，且 `row_bound_applied=false`。因此 DEVNULL 的 first-window 低值或零值不能解释为同一行区间的低内存。
- 本文件只定位下一步 provider 调查方向；不放宽 1.5x、不修改 authority、不选择 Candidate A/B，也不改变 formal no-go。
